# 策研组 · Ceyan Group

**一支为「规划 / 建筑 / 文旅」方案汇报而配的 AI 专家团队：从一个项目背景，做到一份能上台讲的 PPT。**

八个角色，四段流程，每段结束停下来等你签字。不是"一键生成 PPT"，是**把一份方案从定位推到定稿**的那条流水线。

```
立项 ──▶ 文本 ──▶ 视觉生产 ──▶ 收尾
 筑策      析纲        立象         琢磨
 验筹      淬言        落版
   ↑         ↑           ↑            ↑
   └─────────┴───── 司南（每道闸门都在这里）─────┴──▶ 交付
```

---

## 它治的是什么病

绝大多数 AI 生成的汇报 PPT，问题不在排版，在**三件事同时发生**：

1. **定位没站住就动手做图** —— 方向错了，后面七个人都在给错结论做精致包装；等 PPT 出来才发现定位不成立，前面全白做。
2. **一棒理解偏了，六棒跟着错** —— 大纲把"待补"写成结论，润色照样润，排版照样排，最后交付里那页还是空的。中途每一道检查都"通过"了。
3. **字数够了但没人看得见** —— 交上去的文件能改字，可内容跑到画布外、文本溢出、图压在字上。可编辑性和内容可见性是两回事，用一个判据当两个用，等于没查。

这套东西的全部设计，都在对付这三件事。**具体机制见 [docs/设计原则.md](docs/设计原则.md)**，那里每一条规矩都标着它是从哪个真实事故里长出来的。

---

## 谁适合用

- 规划、建筑、景观、文旅策划从业者，要出**概念方案 / 立项 / 投标 / 汇报**类 PPT
- 手里已经有策划报告或大纲，但拆不成页、写不成能念的字、排不成能看的版
- 愿意在四个节点上停下来做决定 —— **这是前提，不是选项**。不愿意被打断的，这套东西会很烦人

**不适合**：要一键出图、不要过程、不接受"停下来确认"的场景。

## 八位成员

| 代号 | 角色 | 只做这一件 |
|---|---|---|
| **司南** | 项目流程总监 | 立规矩、递下一棒、验收。**不写、不做、不替你点头** |
| **筑策** | 项目定位策略 | 把项目问清、做基础分析、收敛定位、落成策划 |
| **验筹** | 商业逻辑审查 | 审定位是否闭环、自洽、有市场支撑，逐条出问题 |
| **析纲** | 大纲与逐页脚本 | 定原则：每页讲什么、用哪几类元素（文本/图表/图片/关系） |
| **淬言** | 文本润色 | 只动文字。不改数字、不改结论、不改结构 |
| **立象** | 视觉表达设计 | 把原则翻译成视觉语言：令牌、页型、蓝图、样张 |
| **落版** | 初稿生成 | 按规格做出**原生可编辑**的 PPTX 初稿 |
| **琢磨** | 逐页精修 | 修客观缺陷、统一全篇、定稿 |

司南不在流水线两端，**在每一道接缝上**。它的权力不来自"指挥"，来自**叫停**。

## 三种用法

### 1. 全链（推荐）

在 WorkBuddy 里选 **「策研组」** 专家团，一句话启动：

> 启动新项目：先出项目章程和台账给我批，批完从段一·立项开始。

司南会按四段推进，每段末停下等你签。

### 2. 单棒

只想干一件事时，直接叫对应专家，不必启动全链：

| 你说 | 叫谁 |
|---|---|
| 帮我理清这个项目 / 定位 | 筑策 |
| 看看这个方案商业上讲不讲得通 | 验筹 |
| 把这份报告拆成 PPT 大纲 | 析纲 |
| 这段话 AI 味太重 | 淬言 |
| 出个视觉方案 / 风格参考 | 立象 |
| 按规格生成 PPT | 落版 |
| 哪几页不好看 / 我手工加了页 | 琢磨 |

### 3. 只借资产

七个 toolkit 里的方法论、判据表、检查脚本可以单独取用，不装专家也能跑。见 [docs/使用手册.md](docs/使用手册.md) 第 5 节。

## 安装

### 前置

- [WorkBuddy](https://www.workbuddy.cn) 桌面端
- Python 3.9+（只有检查脚本需要，不装也能用专家）
- `pip install python-pptx`（只有跑 PPT 检查脚本需要）

### 方式 A：作为插件市场加载（推荐）

```bash
git clone https://github.com/wbczhangpeng-cmd/citybar.git
```

在 WorkBuddy 里把仓库根目录添加为**本地插件市场**。仓库结构就是标准 marketplace 布局：

```
citybar/
├── .codebuddy-plugin/marketplace.json   # 市场清单，指向 plugins/
├── plugins/
│   ├── ceyan-team/                      # 策研组（八人团队，全链用这个）
│   ├── project-orchestrator/            # 司南（单棒）
│   ├── project-positioning-strategist/  # 筑策
│   ├── business-logic-reviewer/         # 验筹
│   ├── ppt-outline-architect/           # 析纲
│   ├── copy-polisher/                   # 淬言
│   ├── visual-design-architect/         # 立象
│   ├── ppt-producer/                    # 落版
│   └── ppt-refiner/                     # 琢磨
└── docs/
```

### 方式 B：直接拷贝

把 `plugins/<你需要的包>/` 整个目录拷进你的专家目录（通常是 `~/.workbuddy/plugins/marketplaces/<市场名>/plugins/`），重启 WorkBuddy。

> **团队包和单棒包的内容已同步**。八个包的 persona 正文逐字节相同，改任一处请跑
> `plugins/ceyan-team/skills/project-orchestration-toolkit/scripts/sync_packages.py`，否则会分叉——单棒走旧规矩、全链走新规矩，这种不一致最难查。

## 工作空间约定（2026-10 新增）

项目开工第一件事是建空间，第二件事是建 `原始资料/`：

```
<项目名>/
  原始资料/
    00-资料台账.md      # 脚本自动维护，你不用手改
    00-外部关联.txt     # 外部目录一行一条，关联进来一样受监控
    01-外部提供/        # 甲方材料、项目信息、意向图
    02-我方回灌/        # 我方后期制作的技术图纸
  交付物/
  00-过程/
  _tools/
```

每一棒上岗前跑一次资料闸，看有没有新料、有没有料被改过：

```bash
python plugins/ceyan-team/skills/project-orchestration-toolkit/scripts/check_raw_materials.py \
    --root <项目空间> --pend 交付物
```

它会把新增文件跟你手上所有「待补」条目做对撞——**这条机制是拿一次真事故换的**：一张 1732×1732 的总平面图在素材文件夹里躺了一整天，四条链都把它当成"待主人补"。
