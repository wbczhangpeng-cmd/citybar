# PPT 大纲工具箱（析纲专用）

给「析纲」专家使用的参考材料。需要时按以下路径读取：

- `references/大纲模板.md` — 可直接套用的逐页脚本模板与文档骨架
- `references/命名风格库.md` — 6 套层级命名风格与命名示例
- `references/示例大纲.md` — 一份完整范例（few-shot，虚构项目，仅供结构参考）
- `references/自检清单.md` — 交付前逐项自检（**§0 叙事** 与 **§D2 文案纯度** 是最容易糊过去的两组）
- `scripts/check_outline_narrative.py` — **交付前必跑**：标题竖读 / 观点重复 / 一页多问 / 七字段完整性 / 文案纯度 / **图片分档与 P 档占比**

## 交付前必跑（v1.2 新增）

```bash
python scripts/check_outline_narrative.py 交付物/step3-02_PPT逐页脚本_v1.md
```

它做两件人做不到的事：**把 55 个标题竖着连起来读**、**算全篇的图片 P 档占比**。

- 读出来像目录（"背景/分析/规划/路径"）→ **这是拆页，回去重排**
- 读出来像论证（"漏在哪/为什么/只能堵三处/先堵哪个"）→ 叙事成立

同时查六项：观点重复 / 并列连接词 / 一页多问 / 七项必备字段缺失 / 文案里含施工指令词 / **图片需求是否分档 + P 档 ≥35% + 有没有"分析图待甲方"这种自相矛盾**。

> **真实事故**：一份 55 页大纲，`check` 报「本页唯一要解决的问题」缺 55 页、「数据或图表」缺 55 页、
> 8 页文案字段装的是"全篇禁用提升优化"这类施工备忘。下游照搬，最后 8 页骨架进了定稿。
> 这些东西靠读是读不出来的——文字完全通顺。

## 使用原则

0. **先读通全文，再判每页。** 不要边读边标"要不要图"——那样标出来的是"这段字旁边能不能塞张图"。正确顺序：通读全文 → 弄清要证明的那件事 → 拆论证链 → 每步一页 → **判这页的内容性质**（判断型/事实型·现场/事实型·数据/关系型/对照型/过程型/清单型/场景型·氛围）→ 内容性质决定表达方式 → 表达方式决定要不要图。**图片需求是最后一步的产物。**
0a. **图片是论证手段，不是装饰。** 六类项目的策划汇报都一样：每页要判 P（必须有图，删了论证不成立）/ S（应该有）/ O（可选）。**P 档 ≥ 全篇 35%**，低于这个数就是资料汇编。**每页都要判，写「可配图」等于没判。**
0b. **先定一个总结论，再排页。** 不写结论就排章节，排出来一定是把原文拆成很多页。判据：**把标题竖着连起来读，读不出一个结论，这份大纲就算有 60 页也是失败的。**
1. **模板是骨架，不是填空游戏**：结构照搬、内容按真实项目重写，禁止把示例里的虚构数据当事实。
2. **示例只借"结构与方法"**，不借"结论与数字"。
3. 交付前必须过一遍 `自检清单.md`。
4. 命名风格默认"常规中文"，用户点名才切换。
