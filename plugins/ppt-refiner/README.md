# 琢磨（ppt-refiner）

把落版交付的初稿，收敛成可以拿出去的定稿。

## 类型

Agent 型（单个 AI 专家）· maxTurns 70 · `06-ContentCreative`

## 它解决什么问题

初稿"能用"和定稿"能发"之间，隔着三件事：

1. **客观硬伤**——文字溢出、元素重叠、对比度不足、图片压坏、页码被盖。这些不需要审美，需要规则和耐心，45 页靠眼睛扫必漏。
2. **全篇不一致**——字号用了 9 种、页码在第 3 页和第 30 页差 4px、同类页的元素一个靠左一个居中、配色越出令牌。单看每页都挑不出毛病，合起来就是廉价感。
3. **重点页"平"**——干净、正确、无硬伤，但没有任何东西让人多看一眼。根源通常是构图，不是字距。

## 它不做什么

- **不重做**。落版已经跟用户确认过的结构改动，只尊重，不推翻
- **不改文案**（归淬言）、**不改数字与结论**（归筑策/验筹）、**不改视觉身份**（归立象）
- **不美化到精致**。它的目标是"收敛到没有明确缺陷"，不是"改到我觉得满意"——后者没有终点，而且会把审美偏好强加给用户

## 两个工作段

| 段 | 改哪里 | 为什么 |
|---|---|---|
| **段一 主体精修** | 项目工作区 `svg_output/` → 重新导出 | 改源头，保住 `spec_lock` 与原生可编辑 |
| **段二 新增页接手** | 导出后的 pptx 上 **append 新页 + 原生绘制** | 用户手工加的页只在 pptx 里，重新从 SVG 导出会把它丢掉 |

## 核心机制

**规则不重写，只补两层。** 客观缺陷直接执行 ppt-master 的 `visual-review` 规则（H1–H9 / S1–S10 / §3 禁改 / §4 回滚）。自己再补两层：跨页一致性、表达强化。

**改动分三级。** L1 自己修（有客观判据）· L2 出前后对比图等用户点头（改构图、改层级、全篇统一）· L3 一律不许（碰上游决策权）。

**可编辑性是放行条件。** 精修是最容易破坏它的环节——为修溢出把文字并成图、为对齐打成组、为好看转曲。所以强制复跑检查、与基线逐页对比，任何一页退化就回滚。

**迭代 2 轮封顶。** 第 3 轮通常说明问题不在手艺而在规则冲突。修不动就写清"为什么"，比再磨一轮有用。

## 两个检查脚本

| 脚本 | 查什么 |
|---|---|
| `check_editability.py` | 单页：整页截图、文字可选中、图表可改数 |
| `check_deck_consistency.py` | 跨页：字号越阶、颜色越令牌、页码漂移、标题错位、密度雷同 |

两个都要跑。前者管"改不动"，后者管"看起来不专业"。

## 依赖

- `python-pptx`、`playwright` + chromium、`Pillow`
- 本机 ppt-master 技能（`~/.workbuddy/skills/ppt-master`）

渲染必须用 chromium，不能用 cairosvg——cairo 没有字体回退链，中文会渲染成方块。
