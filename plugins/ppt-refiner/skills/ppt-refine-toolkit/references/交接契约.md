# 交接契约

---

## 一、接谁的料

| 来源 | 必须拿到 | 缺了怎么办 |
|---|---|---|
| **落版** | ① 初稿 pptx ② **项目工作区路径**（`svg_output/` + `design_spec.md` + `spec_lock.md` + `images/`）③ 偏差记录（完整版）④ 可编辑性验收表（基线）⑤ 已知薄弱页清单 ⑥ 生成报告 | **缺工作区 → 段一没法做**（改不了源）。可以让落版补交，或用初稿 pptx 走一段降级流程（见第四节） |
| **立象** | 设计令牌、页型库、逐页蓝图、图片需求清单、可编辑边界 | 缺令牌 → 越阶判定无从下手。可以让落版从 `design_spec` 里带出来 |
| **淬言** | 强调层级建议、文字量提示 | 缺了也能做，但表达强化时容易误判「哪句是重点」 |
| **验筹** | 可信事实包（含已被否定的假设黑名单） | 缺了不影响视觉精修，但**不能碰任何数字** |
| **用户** | 精修范围意见、调整意见清单、加页文件的体检结果 | 开工第一件事就问 |

**接料体检，一句话报结论：**

> 接料齐：工作区 45 页 SVG、design_spec 含令牌 5 色 7 阶、偏差记录 9 条（结构级 4 条已批）、薄弱页 3 页。可以开工。

或

> 差一件：只有 pptx 没有工作区。这样我改不了源，只能降级成"在 pptx 上做增量修补"，效果会打折。要我去找落版要工作区，还是就这样做？

## 二、交什么给人

### 给「总编排」

| 项 | 内容 |
|---|---|
| 定稿 pptx | 路径 + 页数 |
| 精修报告 | 六件里的第 2 件 |
| **可交付判定** | 可交付 / 补 N 处后可交付 / 不建议交付 |
| 残留项 | 数量 + 每项该找谁 |
| 流程回执 | 两段各做了什么、轮次、渲染次数、耗时、退回记录 |

**"可交付判定"是总编排最需要的一件。** 它决定这份东西能不能进交付包，而不是"再改改"。

### 给用户

只看第一屏：**结论 + 要你定的几件事 + 改了什么（分组）**。

**不要给他 40 条检查项。** 他关心的是"能不能发"和"我要定什么"。

### 给「立象」（退回时）

指出：哪条规则、哪个页型、冲突在哪、为什么页内改不了。

例：
> 页型「论点支持页」定义 3–5 条要点，但 P31 有 6 条且每条 30 字。这页按现定义排不下，缩字号会越阶梯。要么放宽这个页型的条目上限，要么这页换页型。

### 给「淬言」（退回时）

指出：哪一页、哪一句、为什么读不通或超量。

### 给「验筹 / 筑策」（退回时）

指出：哪两处数字打架、缺什么证据。**只指出，不改。**

## 三、什么时候停下不开工

这五种情况，**宁可停下也不动手**：

1. **没有 `design_spec`**（或里面没有令牌与页型定义）→ 改什么都是在猜，"不一致"的基准都没了
2. **没有工作区，只有 pptx** → 只能做增量修补，达不到"按源精修"的效果。**先告诉用户这个折损，再让他选**
3. **没有可编辑性基线** → 复验时无法判断"是它改坏的还是本来就这样"
4. **没有内容可见性基线** → 同上，而且更隐蔽：越界/溢出/碰撞是几何问题，靠肉眼在一页一页里翻几乎看不出来。**可编辑性合格 ≠ 内容能看见**，两条基线必须分别有
4. **用户说"你看着弄，弄好看点"** → 这不是需求，是没定。回一句："那我先按硬伤 + 一致性做，重点页我列 10 页给你挑，行吗"，让他明确
5. **新增页体检不通过**（已有页被改过）→ 停。在被改过的底稿上排版，等于替别人的改动背书

## 四、降级流程（只有 pptx 没有工作区时）

诚实告知折损，然后按这个顺序做：

| 步骤 | 做法 | 折损 |
|---|---|---|
| 1 | 用 `check_deck_consistency.py` 扫全篇 → 拿到一致性问题清单 | 无 |
| 2 | 用 `check_editability.py` 扫全篇 → 拿到可编辑性问题清单 | 无 |
| 3 | 对 pptx 做**增量修补**：能通过 python-pptx 精确改的（位置、字号、颜色、对齐）才改 | **改不了构图、改不了图形组合** |
| 4 | 构图级问题**只记录、不动手**，列进《已知残留》，「建议回落版补出工作区后再精修」 | 部分问题留到最后 |

**必须在报告里写明这次是降级流程。** 否则用户会以为"精修改完了"，实际上构图类问题一个都没解决。

## 五、退货的边界

| 情形 | 退给谁 | 说什么 |
|---|---|---|
| 视觉规范自相矛盾、页型排不下 | **立象** | 哪条规则、哪个页型、冲突在哪 |
| 文案读不通、术语用错、文字超量到排不下 | **淬言** | 哪一页哪一句、超了多少 |
| 数字打架、结论站不住、无出处 | **筑策 / 验筹** | 哪两处、缺什么证据 |
| 页序乱、章节结构有问题、该合并的页 | **析纲** | 哪两页该合并/拆开 |

**"我改得动"不等于"我该改"。** 你改了之后上游不知道，下一轮谁改谁覆盖，最后没人说得清哪个版本是真的——到了评审会上就是事故。

## 六、交接的语言

- **说人话**：「P31 那页字太多排不下，得让淬言压一压」，不说「文本溢出未解决」
- **说数量**：「12 页有硬伤，其中 3 页要你定」，不说「部分页面存在优化空间」
- **说后果**：「这页要再大两号就破字号阶梯，全篇会一起显小」，不说「存在一定冲突」
- **说下一步**：「这条得等验筹补数据，先空着」，不说「建议补充相关资料」

```
【要你定的】
1. P17 删除右下装饰条 · 建议删 · 不删则视觉重心偏
2. P23 收益页第 2 行数字无出处 · 已退验筹 · 这页现在不能发

【改了什么】
硬伤 18 处（溢出 7 / 重叠 3 / 对比度 4 / 对齐 4）
全篇一致性 6 项（正文色统一 47 处 / 页码拉齐 51 页 / 字号 9→7 种）
重点页强化 8 页（构图 5 / 层级 3）
新增页排版 6 页

【可编辑性】51/51 合格，与落版基线一致，零回滚
【内容可见性】越界 0 / 溢出 0 / 碰撞 0，与落版基线逐页一致（临界 2 处，均为 1.6px 量字差）

【残留】P31 文字溢出 —— 6 条×30 字，容器只容 4 条。
       缩字号越阶梯，删条属改内容。建议淬言压到 4 条，或析纲拆两页。

【下一步】上面 2 件定了 + P31 处理完，我 20 分钟能收口。
```
