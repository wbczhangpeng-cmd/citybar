# 契约快照

> 依据 **ppt-master v6.7.3**（`~/.workbuddy/skills/ppt-master`），记录于 2026-10-26。
> 用途：插件升级后**按此比对差异**，而不是靠记忆判断"应该还能用"。

---

## 一、这个专家依赖的三类契约

| 类别 | 契约 | 破了会怎样 |
|---|---|---|
| **规则契约** | ppt-master 的 `visual-review.md` 的 H/S 编号与 §3 禁改清单 | 判据失效，全篇复核变成瞎猜 |
| **脚本契约** | `visual_review.py` / `svg_quality_checker.py` / `svg_to_pptx.py` / `pptx_to_svg.py` 的参数与退出码 | 命令跑不通，流程卡死 |
| **项目结构契约** | `svg_output/` `design_spec.md` `spec_lock.md` `.preview/` `.review/` `live_preview/lock.json` | 找不到输入，或输出写错地方 |

## 二、规则契约（v6.7.3）

### 硬规则编号

```
H1 超出画布     H2 文字溢出     H3 文字重叠     H4 对比度不足
H6 元素碰撞     H7 页眉页脚     H8 图片损坏     H9 必需要素缺失
（H5 字号漂移已由 svg_quality_checker.py 覆盖，不重复查）
```

### 软规则编号

```
S1 行距过紧     S2 留白过空     S3 锚点偏离     S4 对齐漂移
S5 栅格不匀     S6 中文字距     S7 装饰抢色     S8 强调错位
S9 图文关系     S10 breathing 违规
```

### 关键机制

| 机制 | 内容 | 影响本专家 |
|---|---|---|
| **§1.1 品牌令牌升级** | H4 涉品牌令牌时不许页内修，写 `brand_review.json` 升级 | 必须遵守，否则全篇重复违规 |
| **§4.1 迭代预算** | 默认 1 轮，更多需显式开启 | 本专家自定 2 轮封顶，与之一致 |
| **§4.2 回滚终止** | 修完引入新硬伤 → 回滚 + `needs_human` | 直接采用 |
| **§4.3 备份纪律** | 每页首次编辑前备份到 `.review/backup/` | 直接采用 |
| **§5 输出 schema** | 每页 `.review/<page>.json`，含 `findings` / `needs_human_items` / `untouched_concerns` | 直接采用，报告由它聚合 |
| **§3 禁改** | 品牌、结构、内容、其他文件、原子性 | 直接采用，且本专家更严一层（文案/数字一律不动） |

## 三、脚本契约（v6.7.3，脚本均在 ppt-master 的 `scripts/` 下）

| 脚本 | 用途 | 关键参数 / 退出码 |
|---|---|---|
| `svg_quality_checker.py` | 静态检查（字号漂移、ID、XML、画布） | 先跑，不过不进视觉复核 |
| `visual_review.py` | 渲染 PNG 到 `.preview/` | `--pages 03,07`；退出码 **2/3 停止派发**，**4 可复核成功子集但须处理失败页** |
| `svg_to_pptx.py` | 导出原生 pptx | roundtrip 时用 `--roundtrip` |
| `pptx_to_svg.py` | 导入 pptx 为可编辑工作区 | `--inheritance-mode both --roundtrip`（段二备选路径） |
| `beautify_identity.py` | 读源 pptx 画布比例 | 段二核对画布 |
| `svg_editor/server.py` | 预览服务 | `<project> --no-browser`，端口从 `live_preview/lock.json` 发现 |

**渲染必须用 playwright + chromium，不能用 cairosvg** —— cairo 无字体回退链，中文渲染成豆腐块。

## 四、项目结构契约

```
<project>/
  design_spec.md          ← 只读。令牌、页型、逐页蓝图
  spec_lock.md            ← 只读。锁定项，改了会全篇漂移
  svg_output/             ← 段一改这里
  images/                 ← 只读（要换图走 L2）
  .preview/               ← visual_review.py 渲染输出
  .review/                ← 复核结果 + backup/
  live_preview/lock.json  ← 预览端口
  notes/                  ← 演讲备注（只读，属淬言）
  exports/                ← 导出产物
```

**只读清单**：`design_spec.md` / `spec_lock.md` / `images/` / `notes/` / `animations.json` / `image_prompts.json`。

## 五、升级后怎么比对

```bash
# 1. 看版本号变没变
grep -m1 "version:" "~/.workbuddy/skills/ppt-master/SKILL.md"

# 2. 比对规则编号（H/S 有没有增删改）
grep -oE "^\| H[0-9]+" "~/.workbuddy/skills/ppt-master/references/visual-review.md"
grep -oE "^\| S[0-9]+" "~/.workbuddy/skills/ppt-master/references/visual-review.md"

# 3. 比对脚本参数
python "~/.workbuddy/skills/ppt-master/scripts/visual_review.py" --help
python "~/.workbuddy/skills/ppt-master/scripts/svg_to_pptx.py" --help

# 4. 比对 §3 禁改清单（最容易悄悄放宽的地方）
sed -n '/## §3/,/## §4/p' "~/.workbuddy/skills/ppt-master/references/visual-review.md"
```

**改了什么就只改对应的那一块，不要顺手把整个专家重写一遍。** 升级后静默失效是最难查的问题——命令还能跑，只是判据变了，你按旧编号修，规则已经不认了。

## 六、升级影响分级

| 变化 | 影响 | 动作 |
|---|---|---|
| 版本号变、编号不变 | 低 | 看一眼 §3 有没有放宽，然后照用 |
| 新增 H/S 编号 | 中 | 补进执行手册的索引表 |
| 改脚本参数或退出码 | 高 | 改执行手册的命令段，重跑一次验证 |
| 改项目结构（目录名） | 高 | 改交接契约与所有路径引用 |
| 改 §3 禁改清单 | **最高** | 禁改清单是本专家的边界基础，必须逐条人工比对 |
