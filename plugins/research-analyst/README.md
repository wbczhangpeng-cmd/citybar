# 观澜 · 专项调研与产业研究

站在项目最前面的那一棒：把政策、上位规划、标杆案例、市场客群查清核实，出一份**每条结论都能点开出处**的行业研究报告，交给下游做定位判断。

主打文旅、城市更新、产业园区一类的项目前期研究。

## 类型

Agent 型（单个 AI 专家）

## 功能

- **研究命题拆解**：拿到项目章程后，先把「要查哪三层政策、比哪几个案例、验哪几个数、哪些数查不到就认」写成**一页《研究问题清单》**，与下游对完口径才开工。不猜、不铺开就查。
- **政策检索与效力核查**：国家／省／市三层，每条带发文机关、文号、施行期，并判定**现行有效性**（有效／已修订／已废止）。正文不按部门罗列，按**红线／可争取／背书**三类重组。
- **上位规划与合规约束**：从总规、控规、专项规划、生态红线、文保范围里读出**约束条款**，每条落到「哪块地、哪栋楼、哪个指标」。规划里的愿景话术不算约束。
- **案例拆解**：近五年为主，硬指标（客流／营收／平台热度／获奖／报道量／复游率）≥2 项且业内公认才入选。**每个案例自由归因**——区位、客群定位、空间组织、功能业态、营销策划、主题选择、媒体宣传都可能，不套统一模板、不做横向对比；每案 ≥3 条成功点，每条是「具体做法＋证据」。
- **借鉴转化**：所有案例的成功点汇总成《借鉴清单》，每条三段式：别人的做法（带出处）→ 我们该改哪个动作 → 验收标准。
- **市场与客群**：客流总量、过夜率、客源结构、客单价、季节曲线、竞品票价与停留时长、交通半径，每个数都带「谁统计的、什么范围、哪一年」。
- **诚实交付**：查不到的信息不进正文，写进《取证局限》——查了什么、试过哪些入口、为什么受限、影响哪个结论。

## 交付四件

| 文件 | 内容 |
|---|---|
| `行业研究报告.md` | 一页摘要 ＋ 六章（命题与范围／政策／上位规划与合规／案例／市场与客群／启示与建议＋取证局限） |
| `政策清单.csv` | 9 列，30–60 条，含现行有效性 |
| `案例库.csv` | 案例索引（正文另出 md 卡片） |
| `一页结论摘要.md` | ≤600 字，回答「这份研究改变了什么判断」 |

## 边界

**有建议权，无定案权。** 报告里可以写「对本项目的启示与建议（定位／业态／运营）」，但最终方案由下游定位专家定。不做视觉、不做 PPT、不写汇报稿。

## 使用示例

- 我要做一个文旅项目，先帮我查清政策和标杆案例，出一份行业研究报告
- 帮我查清这个项目受哪些国家、省、市政策约束，哪些还有效
- 拆解同类型近几年的标杆案例，看它们各自靠什么成功

## 证据标准

五级：**S** 原始一手／**A** 官方发布／**B** 权威二手／**C** 一般二手（须两源互证）／**D** 推断（不得单独支撑结论）。

每条结论占六行：结论／证据／出处／获取日期／级别／反证。同一关键数字找 ≥3 个独立来源，不一致就报分歧，不取平均。

## 安装

将专家包目录放到专家目录下：

```
~/.workbuddy/plugins/marketplaces/<市场名>/plugins/research-analyst/
```

放好后**重启 WorkBuddy**，专家即出现在专家列表；也可直接从专家市场安装。
## 打包分享

```bash
zip -r research-analyst.zip research-analyst/
```

## 与策研组的关系

观澜是「策研组」九位专家里的第一位。单独安装它可以只做研究；装整套则研究完成后直接进入定位、商业审查、大纲、润色、视觉与出片。

整套获取：<https://github.com/wbczhangpeng-cmd/citybar>
