# 策研组（Ceyan Group）

八位专家合署办公，把一份项目需求做成一份能上台讲的 PPT。

> 一句话：**你只跟司南说话，其余七位的活由它依次叫来干；每干完一段，必须停下来等你签字。**

---

## 为什么要按段停

从一句口头需求到一份可汇报的方案，中间有七个专业判断点。任何一环错了，后面六环都在给错的结论做精致包装——等 PPT 出来才发现定位站不住，前面全部白做。

所以本组只有一条铁律：**每段结束必停，你点头才进下一段。**

---

## 八位成员

| 代号 | 头衔 | 干什么 | 在哪一段 |
|---|---|---|---|
| **司南** | 项目流程总监 | 立章程、递下一棒、过闸验收。不创作任何内容 | 全程 |
| **筑策** | 项目策划与定位顾问 | 把项目情况问清、做基础分析、收敛定位、落成具体策划 | 段一 |
| **验筹** | 商业逻辑审查官 | 审定位是否闭环、自洽、有市场支撑，出问题清单和修正意见 | 段一 |
| **析纲** | 策划方案转PPT大纲专家 | 把策划报告拆成逐页可执行的大纲脚本 | 段二 |
| **淬言** | 汇报文案润色师 | 去 AI 味、修术语、调语气，不动数字和结论 | 段二 |
| **立象** | 视觉表达设计师 | 出设计令牌、页型库、逐页蓝图、样张、图片需求 | 段三 |
| **落版** | PPT生产工程师 | 按设计规格生成完全可编辑的 PPT 初稿 | 段三 |
| **琢磨** | PPT精修定稿师 | 逐页校验、通篇一致性、重点页强化、人工加页排版 | 段四 |

## 四段流程

```
段一·立项    司南立章程 → 筑策定位 → 验筹审查              → 停
段二·文本    析纲出候选章节 →（你选）→ 析纲出《汇报类型卡》→（你选）
             → 析纲展开逐页 → 淬言润色                     → 停
段三·视觉生产 立象出规格 →（你看样张）→ 落版出初稿           → 停
段四·收尾    琢磨精修 → 司南总验收归档                      → 交付
```

**两个新机制（段二起生效）：**

- **汇报类型卡**：析纲先给 4–6 类汇报类型（方案设计／商业立项／产品发布／学术评审／政府汇报／品牌提案／培训宣讲），每类给出「文本／图表／图片／关系图」四元配比与页均字数、页均图位。**你选一类，它成为全篇基线**，单页偏离超 15 个百分点要注明理由。本项目的类型是 A 方案设计汇报。
- **每页补充接口**：逐页脚本里每页最后一行是 `- **补充接口**：`。**你只需在冒号后面写一句话**（多条用 `｜` 分隔），留空就是无补充。下游按棒接力：析纲创建、淬言只搬运、立象定图文关系、落版按四级图源落实到图位、琢磨统一裁切与图注。


每段末司南交一份《交接包》，五件齐全：本段结论、交付物清单、本段遗留、下一棒带什么、闸门结论。

**闸门结论由司南判，但"通过"必须你点头才算。**「无法核验」不等于「通过」。

## 三种用法

**一、跑全链**（主线）
说「启动新项目」，司南先出章程和台账给你批，然后从段一开工。

**二、从中间接上**
说「继续段二，前面都过了」，司南读台账接上，不会重跑前面的活。

**三、只找一个人**
不用启动流程，直接说「让淬言把这段文案去去 AI 味」「让琢磨看看哪几页不好看」。司南单棒直调，但仍受章程约束。

## 关于代问

组员是被唤醒的独立工作者，**它们不能直接和你对话**。任何需要你拍板的事，它们会写进《待确认清单》，每条三样齐全：

> 问题 + 我的推荐答案 + 不确认的后果

司南会一次转达，并保留推荐答案和理由——不会只把问题丢给你。你的回答只有四种：`确认 / 修正 / 驳回 / 待补证据`。

## 交接三核（v1.1 新增）

这三条不是设计出来的，是**跑一次真实项目踩出来的**。58 页真稿从全链跑完，暴露了三个漏洞，每一条都差点让交付带着硬伤过闸。

| 核什么 | 真实事故 | 怎么核 |
|---|---|---|
| **清单真伪** | 析纲的「生僻专名落点表」实测**漏 11 页、误列 3 页**，下游拿它当准绳用了半程 | 抽验 5 条回源头核；1 条错就整张作废重做 |
| **引用存在** | 析纲 → 淬言 → 立象**连续三棒引用同一份从未存在过的文件**（"8 张表明细见附录文档"） | `check_file_refs.py` 机器核 |
| **放行三性** | 「可编辑性 55/55 全合格、图片覆盖 0%」的稿子，实际 **14 页内容在画布外、一页丢了 443 字** | 可编辑性 / **内容可见性** / 事实准确性，三条分别过 |

**共同特征：这三个错误读起来完全通顺。** 清单长得就像对的、描述的东西"应该有"、报告只回答了另一个问题。所以靠读一定会漏，只能机器核。

两个新脚本已放进工具箱：

```bash
# 引用存在性（每道闸门先跑）
python skills/project-orchestration-toolkit/scripts/check_file_refs.py \
    --root . --root 交付物 --include-plugins

# 内容可见性（凡 PPT 交付物必跑）
python skills/ppt-generate-toolkit/scripts/check_content_visibility.py deck.pptx --json vis.json
```

细则：`skills/project-orchestration-toolkit/references/交接核验协议.md`

## 问题回流（v1.2 新增 —— 本组最重要的一次机制修补）

真实跑完一个 58 页项目后发现：

> **7 道闸门全部 pass、0 次退回、10 余条问题被"记账"消化。**
> 析纲 29 页只有施工备忘没有文案 → 落版照搬 → 定稿里 8 页仍是骨架。
> **每一道闸门都"通过了"。**

根因不是人不守规矩，是**「退回」的粒度太粗**：整棒重跑要十几分钟 + 大量上下文，所以永远选"带病前进 + 记账"。

### 改了什么

| 改动 | 内容 |
|---|---|
| **问题归属** | 每条问题必须标 `归本棒 / 归上游·X / 归用户 / 归甲方`。**只有「归甲方（数据缺失）」可以带病前进** |
| **三条禁令** | 不许代改、不许记账了事、**不许另建补充文件绕过**（最隐蔽的一种） |
| **定点回流** | 只把「那几条 + 那几页」交给上游 → 续接唤醒 → 回传 v2 → **只重判改过的地方** |
| **回流上限** | 同一棒最多 2 次，第 3 次升级给你，不许主理人代签「接受带病」 |
| **「有条件通过」收紧** | 只剩一种合法用途：条件来自**外部**（甲方数据 / 你的口径）。来自上游 = 没做完 = 退回 |

闸门结论因此从三档变四档：**通过 / 回流 / 打回 / 外部挂起**。

## 析纲的方法论升级（v1.2）

原来的析纲做的是「把报告**拆成**页」——这就是拆页思维的源头，措辞已经改掉。

现在是**叙事设计三步法**：

1. **先定一个结论**：一句话、≤40 字、必须是**判断句**不是描述句，全篇只服务它。**结论没定，不许排章节。**
2. **按「对方被说服的顺序」排**：立靶 → 归因 → 定点 → 给路 → 兜底，每步至少一页
3. **一页只解决一个问题**：每页必须填「本页唯一要解决的问题」（一句问句）+「核心观点」（一句判断句）

逐页字段从 11 项变成 12 项，新增 **唯一要解决的问题 / 数据或图表 / 画面建议**。

**四条竖读测试**（人做不到，脚本做）：
- 标题竖读：55 个标题连起来读，是目录还是论证？
- 观点竖读：核心观点连起来读，有没有推理链？
- 删页测试：删了之后有页失去支撑的才有存在理由
- 结论回溯：每页能不能回答"我跟那句总结论什么关系"

新脚本：`skills/ppt-outline-toolkit/scripts/check_outline_narrative.py`

## 立象的验证门槛（v1.2）

原来只出 3–5 页样张（覆盖 55 页的 **7%**），蓝图坐标是"算出来的"不是"画过的"。
落版接手后发现 **32 页排不下（真值 54 页 / 175 处）**。

现在两条硬门槛：

1. **样张覆盖每种启用的页型各 ≥1 页**（启用 14 种 → ≥14 页），缺页型必须给你理由并确认
2. **全篇容字预检**：逐页算「正文区可容字数 vs 文案实际字数」，装不下的**不许缩字号压进去**，必须报「建议拆页 / 建议删减到 N 字」——**这是回流触发点**

## 图片：从「配图」升级为「论证手段」（v1.3）

真实跑完一份 58 页文旅汇报，交出来 **0 张图片**。全篇 46 页是纯文字页（连图表表格都没有）。

查下来根因不在落版，在**大纲**：逐页脚本里只有「表达方式：主视觉、构图分区」这类版式描述，
**从来没有一栏回答「这一页需不需要图、图承担什么论证功能」**。落版只能忠实执行一份没有图片需求的脚本。

### 改了三处根本性的东西

**① 大纲：先读通全文，再判每页**

不要边读边标"这段字旁边能不能塞张图"。正确顺序是：

> 通读全文 → 弄清要证明的那件事 → 拆论证链 → 每步一页 → **判内容性质** → 内容性质决定表达方式 → 表达方式决定要不要图

**图片需求是最后一步的产物，不是第一步的判断。** 标完发现"有图也行没图也行"，那不是图的问题，是这页内容性质没判清。

**② 必要性与责任方分开**

| 必要性 | 判据 | 缺了怎么办 |
|---|---|---|
| **P · 必须有** | 删掉图，核心观点站不住 | 不许带病往前走 |
| **S · 应该有** | 助理解，但逻辑不依赖 | 占位 + 进缺口 |
| **O · 可选** | 删了无感 | 可留白 |

**P 档 ≥ 全篇 35%**（文旅/商业综合体/景区类底线）。低于这个数，这份汇报就是资料汇编。

责任方二分法，**这条决定会不会 0 图**：

| 类别 | 含哪些 | 缺了算谁的 |
|---|---|---|
| 可自行产出 | 分析图（自绘）/ 意向图（AI）/ 装饰图 | **我们的活。缺了就是没干** |
| 必须外部提供 | 实景照片 / 效果图 | 甲方。占位 + 缺口 |

那次 0 图的直接原因就是：17 项图位几乎全标"待甲方"，而**动线图、矩阵图、面积分析图本来都是能自己画的**。
**"等甲方"当挡箭牌，挡住了自己的活。**

**③ 表达型：设计的真正第一层**

立象过去一上来就讲色值、字号、坐标——**它只是在把文字摆整齐**，没回答"这页凭什么让人记住"。

现在改成两级，顺序不能颠倒：

- **第一级：表达型 E1–E9**（结论冲击 / 现场图主导 / 图文并置 / 数据主导 / 关系图 / 对照矩阵 / 时间轴 / 清单索引 / 氛围过渡），每页必须归入之一，含图文配比
- **第二级：参数**（色值/字号/坐标）

**表达型一错，后面所有参数都只是在精修一个错误。** 判不出来的页 = 这页有两个核心 = 拆页。

还管一条：**相邻两页的图文配比不要都是 5:5**。连续三页 5:5，读者从第 4 页开始走神。

### 新脚本

```bash
python skills/ppt-generate-toolkit/scripts/check_image_coverage.py \
    交付物/deck.pptx --plan 图位分配表.md --json img.json
```

查四样：覆盖页占比 / 零图页清单 / 图片面积（识别图标充数）/ 对照图位表核 P 档。
退出码 `0` 达标 / `1` 覆盖不足 / `2` **P 档缺图（最严重）**。

**原生图表与表格不算图片** —— 它们承载数据，不是视觉素材。判「是不是图文汇报」只看照片。

## 原始资料闸（v1.5 新增 —— 主人的第 4 条开工铁律）

**只对新项目生效**：已开工的项目不回头改结构。

项目落地第一步不是读资料，是建空间。四类前置条件确认完，还要过这一道：

```
<项目名>/
  原始资料/
    00-资料台账.md      ← 真相源：文件名／子目录／md5／字节／入库时间／提供人／关联页／状态
    01-外部提供/        ← 甲方材料、项目信息、主人给的意向图
    02-我方回灌/        ← 我方后期制作的技术图纸、出给下游的图
  交付物/   00-过程/   _tools/
```

**目录名不写日期。** 日期进台账，不进路径。

**建完文件夹，第一句话就要问主人：现有的料放哪儿？** 不许默认「料会自己出现」。两条路，让主人挑：

| 方式 | 怎么做 | 适用 |
|---|---|---|
| **拷进来** | 文件放进 `原始资料/01-外部提供/`，可分二级子目录 | 料不多、要跟项目一起备份、要长期留档 |
| **关联外部文件夹** | 外部目录绝对路径一行一条写进 `原始资料/00-外部关联.txt`，`#` 开头是注释 | 料在公司盘／网盘／设计院共享目录，不想来回拷，或那份料还在别人手里迭代 |

**关联不等于免责**：外部目录里的文件变了，一样算改动、一样要重判；路径失效单独报一类「外部关联失效」。

**每一棒上岗前自己跑**（不是只有司南跑）：

```bash
python skills/project-orchestration-toolkit/scripts/check_raw_materials.py \
    --root <项目空间> --pend 交付物
```

输出**五类**：新增／改动（md5 变）／删除／未登记（md5 空）／外部关联失效。**任何一类不为空，处置完才能开工。**
新增与改动的文件都会被拆成关键词，去撞 `交付物/` 里所有待补条目——**这一撞就是整个机制的设计目的**。

**三个来源，处置两套**：`01-外部提供` 与外部关联目录 → 有变就走重判；`02-我方回灌` 有变 → 只登记，不重判（自家产出不是新输入）。

### 报问题必须带四件，缺一件不许报

1. **哪份料** —— 文件名 ＋ 出自哪个来源
2. **动了什么** —— 新增／改动／删除；改动要写明 md5 变了，即内容变了，不是时间戳变了
3. **影响哪几页、凭什么这么判** —— 命中的待补条目原文与位置；**命不中也要说清凭什么判它跟当前成果有关**
4. **不改会怎样** —— 具体到哪一页会错、错成什么样

> 只报「有变更」三个字，等于把判断推回给主人。

### 台账无人值守

`00-资料台账.md` 由 `--update` 全自动生成：md5、字节、入库时间、关联页、状态一次写全。**主人一个字都不用改**，手改会在下一次 `--update` 被盘上实测覆盖。

状态三档全自动判：`已用`（交付物里真引用了）／`待用`（对撞命中，该用还没用）／`未用`。

### 它治的是什么病（真事）

滨河生态园项目 `素材/` 里躺着一张 1732×1732 全彩总平面图，10-26 就入库了。段一的筑策读过它，报告里还写着「空间落位可在其上叠加绘制」；**从段二起再没人查过那个文件夹**——析纲把 P32 判成「待主人补：总平面图 1:500」，立象样张 V07 给它画了虚线框，落版按图版占位排，10-27 我还裁了一次「P32 出图版占位」。

**四条链，等的是一张一直在手里的图。** 不是谁偷懒，是没有任何一步要求去看那个文件夹。

### 五类判定实测（不是推演，跑出来的）

| 场景 | 输出 | 退出码 |
|---|---|---|
| 首次无台账 | 新增 N 项 ＋ 对撞命中 | 1 |
| `--update` 后重跑 | 干净 | 0 |
| 追加字节 | 改动 1 项 | 1 |
| 删文件 | 删除 1 项 | 1 |
| 手加行但 md5 空 | 未登记 1 项 | 1 |
| 外部关联目录里的文件 | 标为 `外部关联/<目录名>`，照常对撞 | 1 |
| 外部关联路径被移除 | 外部关联失效 1 处 ＋ 删除 1 项 | 1 |

> **一个坑**：待补条目在语料里有五六种写法——`待补`／`待补·人工`／`{待补：…}`／**`待主人补：…`**／`待确认`／`待出图`。
> 只匹配「待补」两个字会漏掉 `待主人补`，它中间隔着两个字，**不是它的子串**。脚本已按正则收全，别改回去。

| **toolkit 独有文件** | **双向并集**（谁有就合并给谁） | 补进团内 12 项、补进独立 4 项 |
| **toolkit 同名冲突** | **团内为准**（团内是后来重写的精简版，不是丢内容） | 9 项 |

> **为什么不是简单“团内盖独立”**：独立包反而更大——`business-review-toolkit` 独立 52 KB／团内 26 KB，且有 6 份团内没有的专项审查清单（文旅综合体／城市更新／商业综合体／对标基准方法／证据标准与取证手册／审查框架）。**盲目覆盖会直接删掉这些。**

> **为什么同名文件选团内**：团内那批 mtime 更晚、体积更小，是**有意的重写压缩**（例：`交接包模板` 从六字段压到三字段，文件头就写着为什么）。原件全在全量备份里，要抬回来一句话的事。

**补齐的能力缺口**：`project-orchestrator` 原先没有 `ppt-generate-toolkit`，而司南的「交接三核」要跑 `check_content_visibility.py`——已补进该包。

**两条已知的跨包引用**（不是断链，脚本按字面找不到而已）：
- `scripts/check_raw_materials.py` 在 7 个成员包里不存在——**设计如此**，persona 里已注明「用 `ceyan-team`／`project-orchestrator` 包里同一份，三处 md5 必须一致」。
- `templates/design_spec.md`、`references/visual-review.md` 指向 **ppt-master** 的安装目录，不属本组包内。
