# 验收单模板

## 一、三种形态

| 形态 | 什么情况下给 | 后续 |
|---|---|---|
| **过** | 全部判据「过」 | 出下一份交接包 |
| **有条件过** | 无致命缺件，但有可补项 | 列出条件、责任人、闭环时间，进台账「未闭环项」，可继续推进 |
| **打回** | 有判据「不过」且属致命项 | 写明缺什么、退回谁，不许进下一步 |

**「无法核验」的条目不算过。** 若一条判据无法核验而其余全过，判**有条件过**，并把那条列进条件——由用户自行决定是否接受。

---

## 二、验收单结构

```markdown
# 验收单 · <步骤名> → <下一步名>
日期：____        交付物：____（版本）

## 结论：过 / 有条件过 / 打回

## 逐条判据
| # | 判据 | 结论 | 依据 |
|---|---|---|---|
| 2-1 | 整体结论为「可推进/补证后可推进」 | 过 | 结论页写「补证后可推进」 |
| 2-2 | 问题清单无待确认残留 | 不过 | P1-3、P2-1 仍为「待确认」 |
| 2-3 | 黑名单已交付 | 过 | 附件 02-黑名单_v1.md，4 条 |
| ... | | | |

## 无法核验（不算过）
- （判据号 + 为什么核不了 + 需要用户看什么）

## 抽检记录
- 抽检范围：第 3、11、19、27、35 页（每章 2–3 页）
- 抽检项：数字与结论是否与上游一致
- 结果：4 页一致；第 19 页「人均消费 ¥86」与验筹事实包一致，通过

## 条件（仅「有条件过」时填）
| 条件 | 责任人 | 计划闭环 |
|---|---|---|
| 补齐 P1-3、P2-1 的确认状态 | 用户 | 10-27 |

## 处置
- 下一步：进 / 不进
- 若要进，是否需要带上特定未闭环项作为约束：____
```

## 三、写作要求

### 3.1 每条判据都必须有「依据」

**不许只写结论。** 「过」要写过了什么（哪一页、哪份文件、哪个数字）；「不过」要写缺什么。

- ❌ `2-2 | 不过`
- ✅ `2-2 | 不过 | P1-3、P2-1 状态列仍为「待确认」，共 2 条`

依据的作用是**将来可追溯**：三个月后有人问“当时为什么放行”，这份单子是唯一能回答的东西。

### 3.2 抽检必须写范围

有些判据全量核不了（45 页对 45 页比数字），只能抽检。**抽检不是偷懒，但必须公开范围**：

- 抽了几页、哪几页
- 抽检项是什么
- 结论

用户看到“抽检 5 页，其中 P19 有疑点”会自己决定要不要扩大——但你替他隐掉抽检这件事，等于给了他一个假的确定感。

### 3.3 「有条件过」不许和稀泥

条件必须同时具备三要素：**具体内容 + 责任人 + 闭环时间**。缺一项就是「打回」。

- ❌ “建议进一步核实部分数据” → 这是空话，判打回
- ✅ “补齐验筹 P1-3 的确认状态，用户负责，10-27 前” → 合法条件

### 3.4 「打回」要给出可执行动作

打回不是“重做一遍”，要说清：
1. 缺什么（具体到文件和字段）
2. 谁补（哪个专家）
3. 补完之后要不要重新过全闸，还是只补核这几条

**补核即可的不要要求全量重做**——那会浪费一轮并且激怒用户。

## 四、一份完整的验收单（示例）

```markdown
# 验收单 · 验筹 → 析纲
日期：2026-10-26        交付物：02-验筹_审查报告_v1 + 问题清单 + 可信事实包

## 结论：有条件过

## 逐条判据
| # | 判据 | 结论 | 依据 |
|---|---|---|---|
| 2-1 | 整体结论为「可推进/补证后可推进」 | 过 | 结论页：「补证后可推进」 |
| 2-2 | 问题清单无待确认残留 | 不过 | P1-4、P2-2 状态仍为「待确认」（共 2 条） |
| 2-3 | 事实黑名单已交付 | 过 | 附件含黑名单，4 条，均标明来源问题号 |
| 2-4 | 可信事实包已交付 | 过 | 含已核验数据 12 项 + 基准区间 5 组 |
| 2-5 | 取证局限说明存在 | 过 | 第 6 章，写明 3 项该查未查到 |

## 无法核验
- 无

## 抽检记录
- 抽检范围：问题清单中 P0 级 3 条全文核对
- 结果：3 条均有证据链（来源+获取时间+原文片段），通过

## 条件
| 条件 | 责任人 | 计划闭环 |
|---|---|---|
| 处理 P1-4、P2-2 的确认状态（确认/降级/驳回） | 用户 | 10-27 |
| 黑名单 4 条同步进章程第二层 | 秉钧 | 10-26 |

## 处置
- 下一步：进第 3 步（析纲）
- 必须带上的约束：
  · 黑名单 4 条（写入交接包「别踩什么」栏）
  · P1-4、P2-2 涉及的两项数据在页面中一律标「待补」
```

## 五、一个容易忽略的动作

**验收单不是终点，是台账的输入。**

每出一份验收单，立刻更新台账：
- 该步状态
- 交付物路径 + 版本 + 批准人 + 时间
- 新增的未闭环项
- 新增的待办

**验收单和台账对不上，台账就是废纸。** 所以每次更新完跑一次 `scripts/check_project.py`。
