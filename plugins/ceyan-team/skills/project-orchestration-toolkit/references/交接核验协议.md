# 交接核验协议

**这三条是用真实事故换来的。共同特征：出错的产物读起来完全通顺**——大脑会自动补全合理性，靠读读不出来。

---

## 核 1 ｜清单真伪

> 一张"专名落点表"标了 15 个专名的落点页，下游扫后发现**漏 11 页、误列 3 页**，而下游拿它当准绳用了半程。

**规则**：收到清单类产物（索引表／对照表／落点表／覆盖表／页型分配表），**第一件事是抽验，不是引用**。

- 随机抽 **5 条**回源头核
- **1 条错 → 整张作废重做**，不修补
- 5 条全对 → 结论写「抽验 5/5 通过」，**不写「已核实」**

**产出者自己发现不了**：这类产物是机械扫描出来的，生成完就认为完事，**不会回扫**。出错是结构性的。

### 附：清单不能"边改边生成"

> **真实案例**：析纲改了正文几页，然后重建分配表——但重建发生在内容改完**之前**，结果表里还留着旧标题。表 43 行、正文 45 页，两者对不上。**是它自己写的一致性脚本抓出来的。**

**规矩：清单必须在所有内容改完之后再生成，不能边改边生。**

原因：清单是**指向内容的索引**。内容还在动的时候生成索引，索引必然追不上。而它错得很隐蔽——**表格看起来完整、行数看起来对，只有逐行比对才发现。**

**操作顺序固定为**：① 改完所有内容 → ② 重新生成清单 → ③ 用脚本逐行比对清单与正文 → ④ 对不上就不算完成。

## 核 2 ｜引用存在

> 写「8 张表见附录文档」，下一棒照引用，再下一棒照排版——**连续三棒引用同一份从未存在过的文件**。

**规则**：交付前跑一遍，别用眼睛。

```bash
python <包>/skills/project-orchestration-toolkit/scripts/check_file_refs.py \
    --root . --root 交付物 --include-plugins --ignore 'design_spec\.md$'
```

报「缺失」→ 补建，或把引用改成真存在的东西。**两条路选一条，不许放任。**
报「路径不符」→ 文件在但路径写错，改路径。

---

## 核 3 ｜放行三性

> `check_editability.py` 报 全页合格、图片覆盖 0%，据此判过闸。实际 **多页内容在画布外、多页文本排不下**（一页丢整段文字，一页整张表在画布外（y 远超画布边界）高 1080）。
> 根因：这个脚本只查"是不是图片冒充"，**完全不查"内容在不在画面里"**。两个判据正交，拿一个当两个用了。

三条判据**分别**过：

| # | 问什么 | 不过的后果 |
|---|---|---|
| ① 可编辑性 | 是位图冒充的吗 | 对方打开改不了字 |
| ② **内容可见性** | 内容在画面里吗、装得下吗、压住别人了吗 | 观众看不到，等于没做 |
| ③ 事实准确性 | 数字／结论／口径被改了吗 | 汇报当场被问住 |

**「临界」不算不合格，但必须看**——字体替换、缺字、软件版本差异都可能让它们真的溢出。

**三条里过两条不叫过，叫漏了一条。**

---

## 两个量具陷阱

**① 倍数行距做版面计算，永远是估算。** PowerPoint 百分比行距乘的是字体自带单行高（Noto Sans SC = 1.20em），155% 实际每行 1.86em；按 1.49em 估算少算 25%，于是"构建认为排得下、审计判为溢出"。**能落绝对磅值就别用倍数。**

**② 用自建渲染器验收，第一个要验的是渲染器本身。** 两次误报追下去都是渲染器坏了（`overflow:hidden` 裁掉表格末行），稿子本身没问题。**"目视通过"很可能只是看见了自己的尺子。** 查到是量具的错就改量具，**不要改稿把问题抹平**。

## 问题归属与回流

每条问题必须带一个归属，**没有第五条路**：

| 归属 | 处置 |
|---|---|
| **归本棒** | 就地改，记账 |
| **归上游·X** | **必须回流** |
| **归用户** | 进待确认清单，等主人回话 |
| **归甲方** | 标 `{待补}`。**唯一合法的"带病前进"** |

### 归上游的三条禁令

1. ❌ **不许代改**——下游替上游改内容，等于改别人的结论
2. ❌ **不许记账了事**——问题会原样出现在成稿里
3. ❌ **不许另建补充文件绕过**——最隐蔽，看起来没动别人东西，实际替上游擦了屁股

> 第 3 条真实发生三次，全都"形式合规、实质失效"：出「补正表」→ 从此两张表说不清哪张准；让下一棒新建附录 → 该补的约定还是没人补；自己修完并回 → 没人核过别处是否同病。
> **判断标准：你做的事，上游那棒自己没做，那就是绕过。**

### 回流是「定点重入」，不是「整棒重跑」

整棒重做成本太高（十几分钟 + 大量上下文），**这才是过去没人愿意退的真实原因**。

1. 只取 `归上游·X` 的条目 + 页码／字段位置
2. **续接唤醒**那一棒，只说「只改这几处，别动其他」
3. 回传 v2，**v1 不覆盖**
4. 你**只重判改过的地方**
5. 转回给下游，由它说一句「这条我认了」

**上限：同一棒最多 2 次。** 第 3 次说明问题超出它能力，或你的判据本身有问题——**升级给主人，不许代签"接受带病"。**
