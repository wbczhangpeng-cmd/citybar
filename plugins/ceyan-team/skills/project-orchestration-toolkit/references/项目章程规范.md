# 项目章程规范

**章程是一页纸，不是规则手册。** 它只做三件事：统一底线、给本项目加严、说清谁能定什么。

**不写流程**（在放行判据里），**不写检查项**（事后用），**也不管体例**。

## 模板

```markdown
# 项目章程 · <项目名> v1

## 一、共同底线（所有人必守）

1. **不编数** —— 论证据类数字无出处就标「待补」。**但设计参数要敢给**——那是专业判断，不是事实主张。
2. **不改他人结论** —— 发现上游有错，报告并退回，不自己改。
3. **不越位** —— 只做自己那一段。不替下游做设计，不替上游做定性。
4. **主人未确认的，不当成既定前提**。

## 二、本项目加严项（这类项目最容易在哪出错）

<3–5 条，每条一句。不写通用套话。>

## 三、决策权限

| 事项 | 谁定 | 谁只能提议 |
|---|---|---|
| 项目方向（定位/主题） | 主人 | 筑策提议、验筹质疑 |
| 章节结构 | 主人（可委托筑策翻译） | 析纲提议 |
| 视觉身份 | 主人（看样张点头） | 立象提议 |
| 精修范围 | 主人（清单优先） | 琢磨提议 |
| 专业判断（业态、结构、动线、技术） | 对应专家 | 其他专家不越位 |
| 放行与否 | 秉钧 | 各棒自评 |

## 四、锁定参数

| 参数 | 值 |
|---|---|
| **项目类型（文旅／住宅／商业综合体／城市更新／片区／园区…）** | **必填。先定类型，再定其余——它决定观澜查谁的文、筑策搭哪层、验筹用哪本册、析纲套哪个骨架** |
| 受众 / 汇报时长 / 交付形态 | |
| 主人的专业角色（决定第 5、6 步怎么交接） | |

> 类型未定就开章程，等于让八个人各自猜一遍。**猜错的成本不是返工一次，是每条链都归错位。**
```

## 三条纪律

**① 加严项必须具体。**
❌「注重文化准确性」
✅「不许把有学术争议的内容当定论；出现争议内容必须标'另有考证'」

**② 权限表必须写明"谁定了算数"。**
本组已发生：方向改了三轮才定，因为没人说清谁能拍。**写进权限表就不会再发生。**

**③ 章程批了才动工，但章程可以改。**
改章程要主人同意，且要**回头检查已做部分是否需要重做**。

## 一个反例

上一版章程有六节，含「交付体例统一」「编号稳定」等条款。实际效果：**专家花时间维护编号和体例，而不是做内容。**

**章程不该管体例。** 体例是专家自己的事，主人只看结果能不能用。
