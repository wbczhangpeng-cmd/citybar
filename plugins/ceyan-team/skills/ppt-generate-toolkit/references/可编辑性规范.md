# 可编辑性规范

用户的原话是"最终成稿必须是完全可编辑的 PPT 文件"。这条在你这儿就要守住——**到琢磨阶段再救，已经晚了。**

## 一、五条硬约束

| # | 约束 | 理由 |
|---|---|---|
| 1 | 文字一律**原生文本框**，不转曲、不贴图 | 转曲后改一个字要重画整句 |
| 2 | 图表用**原生图表对象**（可改数据） | 贴图意味着数据一变就得重做 |
| 3 | 表格用**原生表格** | 同上 |
| 4 | 复杂关系图用**原生形状拼**，不许整页截成一张图 | 这是最大的破口 |
| 5 | 图片只用于照片、意向图、图纸，**不承载文字信息** | 图里的字等于不可改的字 |

## 二、红线

**任何一页出现"整页截图"，直接判不合格返工。**

判断标准：该页承载信息的元素（文字、图表、表格、关系图）中，有**任何一类**只能以位图形式存在 → 不合格。

允许的位图只有三种：照片（实景/意向/氛围）、图纸（平立剖/总图）、合规地图底图。

## 三、验收表

导出后逐页填，别用"整体感觉"代替：

| 页码 | 文本对象数 | 图表（原生/位图） | 表格（原生/位图） | 图片数 | 整页位图 | 判定 |
|---|---|---|---|---|---|---|
| P01 | 1 | — | — | 1（背景） | 否 | 合格（背景图不承载信息） |
| P12 | 6 | — | — | 0 | **是** | **不合格·返工** |

判定口径：
- **合格**：文字可选中、图表可改数、无整页位图
- **有条件合格**：用了位图但仅为照片/图纸/底图，且不承载信息 → 记一句说明
- **不合格**：整页截图、图表是图、表格是图、文字转曲

## 四、自动检查

工具箱里带了一个脚本，导出后跑一次：

```bash
python "<专家包>/skills/ppt-generate-toolkit/scripts/check_editability.py" "<pptx路径>"
```

它逐页统计：文本对象数、原生图表数、原生表格数、图片数、组合数，并把"疑似整页位图"的页标出来（图片面积占比 ≥85% 且该页文本对象数为 0）。

输出是终端表格 + 一份 JSON，直接贴进验收表。

**这不是替代人工看，是保证不漏页。** 45 页靠眼睛扫，一定漏。

## 四之二、内容可见性（独立判据，不能省）

**可编辑性过了 ≠ 内容能看见。这两个判据是正交的，拿一个当两个用就会漏。**

| 判据 | 问的问题 | 脚本 |
|---|---|---|
| 可编辑性 | 这一页是不是位图冒充的？ | `check_editability.py` |
| **内容可见性** | 内容在画面里吗？装得下吗？压住别的东西了吗？ | `check_content_visibility.py` |

> **真实事故**：`check_editability.py` 报 **55/55 全合格、图片覆盖 0%**，据此判定过闸。
> 实际有 **14 页内容落在画布外、23 页文本排不下**——一页丢了 443 字正文，
> 一页整张表在 y=1248（画布高只有 1080），一页整块冲突卡在画面外看不见。
> 根因就是这一条：可编辑性脚本完全不查"内容在不在画面里"。

```bash
python "<专家包>/skills/ppt-generate-toolkit/scripts/check_content_visibility.py" "<pptx>" --json vis.json
```

查三样：

1. **越界** —— 形状右/下边缘超出画布。`x < 0` 视为刻意的出血装饰，不判。
2. **溢出** —— 按字体实测宽度换行后，所需高度超过框高。
3. **碰撞** —— 溢出的文本压到下方同列其它形状（垂直侵入 > 6px）。

退出码 `0` = 三项全 0。另有**「临界」档**：已超出但在容差内，**不算不合格但必须看**——字体替换、对方机器缺字、软件版本差异，都可能让它们真的溢出。

### 为什么估不准（这条一定要知道）

PowerPoint 的**百分比行距乘的是字体自带的单行高**，不是字号。Noto Sans SC 单行高实测 = 1.20em，那么 155% 行距实际每行 = 1.20 × 1.55 = **1.86em**。若按 1.49em 估算，**整整少算 25%**，于是出现"构建认为排得下、审计判为溢出"，自己跟自己打架。

**对策：能落绝对磅值（`spcPts`）就别用倍数行距。** 落了绝对值，任何量具读到的都是 PowerPoint 真正渲染的那个数。

### 还有一条：自建量具先自验

若自己写了渲染器或审计脚本做验收，**第一个要验的是它自己**。真实发生过两次误报，追下去都是渲染器坏了（表格容器 `overflow:hidden` 裁掉末行），稿子本身没问题。

> 用自建的尺子量东西，"目视通过"很可能只是看见了自己的尺子。

查到是量具的错就改量具，**不要顺手改稿把问题抹平**——那是把别人的正确改成自己的错误。

## 五、常见翻车与修法

| 症状 | 原因 | 修法 |
|---|---|---|
| 整页文字改不动 | 背景图里烧进了文字 | 背景图去字 → 文字重新用文本框排 |
| 图表数据改不了 | 用了截图或 SVG 渲染图 | 换原生图表对象，重灌数据 |
| 关系图一挪就散 | 用了独立线段而非绑定连接线 | 重画：形状 + 绑定连接线 |
| 表格错行 | 用了多个文本框拼表格 | 换原生表格 |
| **导出的 PPT 里内容不见了 / 半截 / 跑到页外** | 内容在画布之外或框装不下 | 跑 `check_content_visibility.py` 定位，改框或减字；**不要靠"打开看看"** |
| **同一份稿子两次量出不同结论** | 用了倍数行距做计算（少算 25%） | 改绝对行距 `spcPts`，再复量 |
| 字体在自己机器上正常、客户机器上变形 | 用了客户没有的字体 | 换通用字体族，或随稿附字体说明 |
| 半透明遮罩盖住文字 | 遮罩压在文本框之上 | 调层级：遮罩在下，文字在上 |

## 六、和"好看"的取舍

**完全可编辑和视觉极致精致有天然张力。** 原生形状拼出来的复杂图形，永远不如一张精修 SVG 好看。

立象在 `design_spec` 里为每种页型声明了"可编辑边界"——哪部分是原生、哪部分允许是图。**你按那个边界执行**：
- 边界内允许用图的，用图
- 边界内要求原生的，就算难看也得原生

**发现规范本身逼着你违反可编辑性时，退回立象，不要自己发明折中方案。** 你造的折中，下一棒看不懂。
