# 改动分级与审批

> 精修阶段最大的失控方式：改着改着，把一页改成了另一页。
> 这份文件的作用是**在你动手之前，先确定这次改动该由谁拍板**。

---

## 一、三级表

| 级 | 判定标准（一句话） | 谁定 | 怎么留痕 |
|---|---|---|---|
| **L1 自动修** | 有客观判据、且不改变设计意图 | 你自己 | 改动记录（全量） |
| **L2 先给用户看** | 要改变构图、层级、或需要全篇统一 | 用户点头 | 前后对比图 + 改动记录 |
| **L3 一律不许** | 属于上游的决策权 | 退上游 | 退货说明 |

**判定口诀**：这次改动，能不能用规则原文的某一条直接说明它对？能 → L1。要靠我的判断？→ L2。要改上游定过的东西？→ L3。

---

## 二、L1：什么可以自己动手

| 类型 | 具体 | 依据 |
|---|---|---|
| 硬规则修复 | H1 出界、H2 溢出、H3 重叠、H4 对比度（非品牌令牌）、H6 碰撞、H7 页眉页脚、H8 图片坏、H9 元素缺失 | 规则原文 §1 |
| 对齐与节奏 | S1 行距、S2 空心、S4 对齐漂移、S5 栅格不匀、S6 中文字距 | 规则原文 §2 |
| 字号越阶 | 某页用了阶梯外的字号，调到最近阶梯 | 令牌 |
| 配色越令牌 | 用了令牌外的颜色，改回最近令牌 | 令牌 |
| 位内图适配 | 图片比例与原槽位不符，等比缩放 + 居中裁切 | 不改分区 |
| 强调微调 | 在角色锚点 ±2px 内调整字号 | 规则 §3 允许 |

**L1 也要记账。** 不记账等于没改——交付时用户问"你把 P23 那个字挪了？"你答不上来，那就是黑箱。

---

## 三、L2：什么必须先问

| 类型 | 为什么必须问 |
|---|---|
| **页内构图重排** | 改分区比例 = 改设计意图。同一页 60/40 和 50/50 在两个方案里可能是刻意做的区分 |
| **强调层级调整** | 你放大哪一句，等于替用户决定讲什么。他会觉得"这不是我想强调的" |
| **删装饰** | 装饰可能是品牌资产（立象的定义），你看着多余，别人看着是识别度 |
| **换版式变体** | 版式库内换可以，但换完这页与同类页就不一样了，需要用户知道 |
| **全篇统一方案**（deck_wide） | 影响全部页，必须一次批准 |
| **任何"我觉得这里更好"的改动** | 只要判据不是规则原文，就是 L2。没有例外 |

### L2 的交付形式

**必须出前后并排图**，不要用文字描述。理由很实际：你说"我把主图放大了、说明区收窄到 34%"，用户脑子里得画一遍；给他看图，两秒就判断了。

格式：

```
P17 · L2 · 构图重排
改前：图 50% / 文 50%（等分，无主次）
改后：图 64% / 文 36%（主图确立，文字收紧为 3 条）
理由：这页的核心信息是"现状与目标的空间落差"，需要先看图
代价：说明只剩 3 条，原第 4 条（运营模式）建议移到备注
[改前.png] [改后.png]
```

**每条 L2 都要写"代价"。** 只讲好处的改动一定藏着问题。

## 四、L3：什么碰都不许碰

| 想改的东西 | 归谁 | 怎么说 |
|---|---|---|
| 配色角色、字号阶梯、页型库定义 | **立象** | 指出哪条规则、哪个页型、冲突在哪 |
| 文案词句、措辞、语气 | **淬言** | 指出哪页哪句、为什么读不通 |
| 数字、口径、结论 | **筑策 / 验筹** | 指出哪两处打架、缺什么证据 |
| 页序、章节结构、页数 | **析纲** | 指出哪两页该合并 |

### 最容易越界的三件事

1. **"这句话不通顺，我顺手改一下"**
   你改了，淬言不知道。下一次它基于旧文案再润一遍，你的改动就被覆盖了。而且用户会以为是淬言改的。

2. **"这个数看起来不对，我改一下"**
   绝对禁止。这是整条链最严重的事故——精修是最后一个动文件的人，出了错没有下一道防线。

3. **"这两页内容重复，我合并一下"**
   页序是用户逐章确认过的。合并等于改结构。

**遇到 L3，正确动作是：停手、记录、报给用户、说明退给谁。** 不要"我先改了再告诉他"——那是最坏的做法，因为用户失去了判断的机会。

## 五、边界模糊时怎么办

有些情况不在表里。判法：

```
问自己：如果用户看到我这么改，他会说"对，我就是这个意思"，
       还是"咦，我没让你动这个"？
```

- 前者 → L1
- 后者或不确定 → **L2**
- 涉及文案/数字/结构 → **L3**

**不确定就升级一级。** 多问一次的代价是一分钟，改错一次的代价是重做一页甚至一整章。

---

## 六、用户的清单优先级最高

用户在开工时可能会给你一份《调整意见清单》。规则：

| 情形 | 处理 |
|---|---|
| 清单项与视觉规则一致 | 直接执行，不必再确认 |
| 清单项与规则冲突（如"字号再大两号"越出阶梯） | **先按用户说的做，同时标出后果**。规则不该赢过用户的明确指令 |
| 清单项涉及 L3（改文案、改数字） | 告诉用户"这条要退给淬言/筑策"，不自己动 |
| 清单项之间互相矛盾 | 指出来，让用户定，不要自行取舍 |

**"先按用户说的做，同时标出后果"** 这句话是这份文件的重点。它避免了两种坏做法：一种是固执地守着规则不听人，一种是默默地照做然后出事。

正确的输出长这样：

> P08 字号按你说的从 32 提到 40。提醒一句：全篇有 14 处用了 32，单独这页提到 40 会显得跳。如果你要的是"这页更醒目"，另一条路是把其他内容降一级。你说哪种。

## 七、改动记录格式（和落版的偏差记录对齐）

```markdown
| 页 | 级别 | 改了什么 | 依据 | 影响 | 状态 |
|---|---|---|---|---|---|
| P03 | L1 | 标题框右移 6px 对齐栅格 | S4 对齐漂移 | 无 | 已改 |
| P07 | L1 | 正文 15pt→16pt | 字号阶梯 | 该页正文多 1 行，已确认不溢出 | 已改 |
| P12 | L2 | 图 50%→64%，说明收为 3 条 | 构图重排 | 第 4 条移备注 | 用户已批 |
| P17 | L2 | 删除右下装饰条 | 装饰抢主视觉 | 需确认是否品牌资产 | **待批** |
| P23 | L3 | 收益测算第 2 行数字无出处 | 事实存疑 | 已退验筹 | 已退 |
| P31 | — | 修溢出需并成图，放弃 | 违反可编辑红线 | 进残留 | 残留 |
```

**"状态"列不能空。** 待批、已批、已退、残留——四种状态必须明确。交付时用户只看这一列就能知道还有哪些事没闭。
