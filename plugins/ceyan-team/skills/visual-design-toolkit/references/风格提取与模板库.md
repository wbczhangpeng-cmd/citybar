# 风格提取与模板库

用户给你一堆"我觉得好的"文件，你要把它们变成**一套可复用的、带参数的模板**。这件事的难点不在提取，在**不一致时怎么办**。

## 一、两条入口

| 入口 | 触发 | 处理 |
|---|---|---|
| 单份参考 | 一个 PPT / PDF / 图片 / 一段风格描述 | 出一张《风格指纹卡》→ 直接转模板 |
| 样本文件夹 | 用户把多份文件丢进一个目录 | 逐份出指纹卡 → 聚类 → 冲突先问 → 转模板 |

支持格式：`.pptx` `.pdf` `.png` `.jpg` `.jpeg` `.html`
（`.key` 无法直接解析时，请用户导出为 pptx 或 pdf）

## 二、扫描流程（folder scan）

1. **先告知扫描清单**：列出找到的 N 个文件与各自页数，让用户确认范围
2. **全量扫完再一次给结果**。**不要逐个文件问"要不要纳入"**——那会把这件事变得很烦，用户会中途放弃
3. 逐份出《风格指纹卡》
4. 聚类合并（见第四节）
5. **冲突时停下来问**（见第五节）
6. 转模板入库 + 更新索引

## 三、风格指纹卡（每份文件一张）

```markdown
# 风格指纹卡 · <文件名>

- 有效页数：<N> 页（封面/尾页不计）
- 一句话印象：<≤20 字>
- 关键词：<5–8 个>

## 色彩
| 角色 | HEX | 面积占比 | 用途 |
（面积占比可从页面像素统计粗估，标注"粗估"）

## 字体
- 中文字族（识别到/推断）
- 西文与数字族
- 字号阶梯（按页面标题/正文/注释三档量出相对倍率，如 1 : 0.6 : 0.4）
- 字重使用习惯

## 版式
- 画布比例
- 每页平均模块数
- 留白比例（粗估）
- 常用分区比例
- 网格感（有无可见栅格/卡片）

## 图表
- 常用图型
- 是否带网格线、坐标轴风格
- 数据标签习惯
- 是否用 3D / 渐变 / 阴影

## 图片
- 裁切比例
- 圆角
- 是否叠加色块
- 图片占版比例

## 装饰
- 允许的装饰元素
- 明显禁止的元素

## 各类页面特征
（逐条对应 15 种页型，只写有证据的；没有的写"未见"）
```

## 四、聚类规则

从多张指纹卡合成一套模板时：

1. **色彩**：按面积占比加权取众数，不取平均（平均会得到一堆"灰褐"，谁的个性都没有）
2. **字体**：取出现频次最高的字族；若两份文件字族完全不同，视为两组风格，不要合并
3. **版式密度**：按"每页模块数"分档（≤3 稀疏 / 4–6 中等 / ≥7 密集），取主档
4. **图表与图片**：取多数派；少数派做法记入"变体"而非丢弃
5. **一致度评分**：给一个 0–100 的粗分（色彩 40 / 字体 20 / 版式 20 / 图元 20 加权），**低于 60 就说明这批文件不是一种风格**

## 五、冲突处理（关键）

**绝不自行融合。** 两种风格缝在一起必然得到四不像，而且用户会认为你没看懂。

发现冲突时，输出这样一段：

```
这批样本分成两组，差异无法调和的点有三处：
| 维度 | A 组（≤3 份） | B 组（≤3 份） |
| 主色 | 冷青 #1F3A34（占 62% 面积） | 暖褐 #7A4A2B（占 55% 面积） |
| 版式密度 | 每页 4–5 模块 | 每页 2–3 模块，大量留白 |
| 字体 | 思源黑体 | 宋体 + 楷体标题 |

请选一种处理方式：
1. 以 A 组为主（B 组只借其图片处理方式）
2. 以 B 组为主
3. 各出一套模板（推荐，两套都入库，按项目选用）
```

**推荐永远是"各出一套"**——两套模板的存在成本几乎为零，而缝成一套的返工成本很高。

## 六、阈值与例外

- 有效页 **≥3 页**才出模板
- 1–2 页：标"样本不足，仅作参考"，说明缺什么（如"缺数据图表页样本，图表语言无法提取"）
- 纯图片样本（无 PPT/PDF）：只能提取色彩与图片处理，**必须明说"版式与字体无法提取"**

## 七、《风格总结》模板（用户确认用）

```markdown
# 风格总结 · <模板名>

## 一句话定位
<≤24 字，例：冷调新中式，重结构轻装饰，适合政府正式汇报>

## 关键词
<5–8 个>

## 色彩
| 角色 | HEX | 用途 | 面积上限 |

## 字体与字号
| 层级 | 字族 | 字号 | 行高 | 字重 |

## 版式
- 画布 / 栅格 / 边距
- 常用分区比例
- 每页模块数区间

## 图表语言
<图型偏好、轴与网格习惯、标签习惯>

## 图片处理
<裁切比例、圆角、叠加、占版比例>

## 装饰
- 允许：<>
- 禁止：<>

## 各类页面表达特征
（逐条对应 15 种页型，无样本的标"待补"）

## 提取依据
- 来源文件：<清单>
- 一致度评分：<0–100>
- 无法提取项：<列出>
```

**这份必须经用户确认后才入库。** 别自己认定"就是这样"，然后污染了整个模板库。

## 八、入库结构

```
<模板目录>/<template_id>/
├── style.md            # 《风格总结》定稿（即令牌全集 + 页型特征）
├── preview.png         # 预览图（必填！1–2 张）
├── fingerprint/        # 原始指纹卡，可追溯
│   └── <file>.md
└── meta.json           # 来源、版本、一致度、关键词
```

`meta.json` 字段：
```json
{
  "template_id": "cold-new-chinese",
  "name": "冷调新中式",
  "version": "1.0.0",
  "source": ["xx汇报_2025.pptx", "yy方案.pdf"],
  "extracted_at": "2026-10-26",
  "consistency_score": 78,
  "keywords": ["冷调", "新中式", "结构感", "低饱和"],
  "note": "缺图版页样本，图片处理为推断"
}
```

**预览图是必填项。** 没有预览图的模板库，三个月后用户分不清谁是谁。

## 九、调用方式

立象启动时：
1. **先检索已有模板**（读索引 + 关键词匹配项目类型与受众）
2. 命中则提议："库里有一套『冷调新中式』，与本次政府汇报场景接近，是否作为基底？"
3. 三种用法：**整套复用** / **以模板为基底 + 项目化微调**（改主色、换字体、调密度）/ **不用**
4. 微调结果**不覆盖原模板**，另存为新版本或新模板

## 十、归因与版权

- 每套模板记录来源文件，标注"据 XX 提取"
- 提取出的是**风格参数**（色值、比例、密度），不是原文件的版式文件本身——这一点要在模板说明里写清
- 原文件含客户敏感信息时，只提参数，不复制原文任何文字内容
