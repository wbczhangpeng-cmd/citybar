# 生成报告模板

交付时给用户的正式说明。**一页能看完，不要写成日志。**

## 一、生成报告（主体）

```markdown
# 生成报告 · <项目名>

## 结论
- 页数：计划 <N> 页 / 实际 <N> 页
- 交付状态：<可直接进入精修 / 有 X 处占位待补 / 有 X 页需你先定>
- 质量门：最终门 <通过 / 通过带警告>；可编辑性 <合格 N 页 / 不合格 0 页>

## 页型使用
| 页型 | 页数 | 占比 | 页码 |
|---|---|---|---|
| 论点支持页 | 18 | 40% | P04–P09, P12–P18 … |
| 数据图表页 | 9 | 20% | … |
| … | | | |

## 图片状态
| 状态 | 数量 | 页码 | 说明 |
|---|---|---|---|
| 已落地（实景/图纸） | 6 | P02, P07 … | 甲方提供 |
| 已生成（意向图） | 4 | P13, P21 … | 已标"意向图" |
| 待甲方提供 | 5 | P05, P11 … | 见缺口清单 |
| 待确认 | 1 | P28 | 授权待核 |

## 偏差摘要
- 微调 <X> 条（明细见偏差记录）
- 结构改动 <Y> 条（均已获确认：<哪一轮>）
- 方法级建议 <Z> 项（建议上游修订）

## 缺口清单（详见下节）
- 共 <X> 项，其中影响正文论证的 <Y> 项

## 已知薄弱页
| 页码 | 为什么薄弱 | 建议怎么处理 |
|---|---|---|
| P31 | 数据只有两年，趋势图说服力弱 | 补第三年数据，或改为对比表 |
| P38 | 三张图比例不一致，临时裁切过 | 等甲方补同比例原图后替换 |
```

## 二、缺口清单（单独一节，逐项）

| 编号 | 页码 | 缺什么 | 谁该提供 | 影响 | 当前处理 |
|---|---|---|---|---|---|
| G01 | P05 | 主入口实景 | 甲方 | 图版页少一张主图 | 已占位 |
| G02 | P17 | 目标年客流预测值 | 筑策 / 验筹 | 收益测算无法上图 | 已占位 `{待补}` |
| G03 | P28 | 第三年运营数据 | 甲方 | 趋势判断偏弱 | 改为两年对比 |

要求：
- **"影响"写清楚**，让用户能判断优先级
- **不合并同类项**（"缺若干数据"这种写法等于没写）
- 缺口多的项目，按"影响论证 → 影响观感 → 仅影响美观"排序

## 三、可编辑性验收表

| 页码 | 文本对象 | 原生图表 | 原生表格 | 图片 | 整页位图 | 判定 |
|---|---|---|---|---|---|---|
| P01 | 4 | 0 | 0 | 1 | 否 | 合格 |
| … | | | | | | |

末尾一行总结：`共 N 页，全部合格；图片 N 张，其中承载信息 0 张。`

## 四、流程回执（给总编排，不写给用户看的部分可省略）

```
路线：Generate — Default
模板：<本项目 Style 模板 id / 自由设计>
模式：<split / continuous>
页数：<N>；分批：<5 + 10 + 10 + …>
质量门：早期门 <结果>；最终门 <结果>；图片终态 <结果>
重试记录：<问题 | 尝试轮数 | 结果>
耗时：<粗略>
产出：exports/<file>.pptx
上游退回：<无 / 退给谁 / 原因>
```

## 五、写这些的时候别犯的错

- **不要报"已完成"就完事**。有占位、有薄弱页、有结构改动，必须在报告里出现。
- **不要把报告写成过程日志**。"执行了 7 个步骤、跑了 3 次检查"对用户没有价值。
- **不要用形容词代替数字**。"整体效果良好"是废话；"18 页论点支持页，占 40%，与目标区间一致"才是信息。
