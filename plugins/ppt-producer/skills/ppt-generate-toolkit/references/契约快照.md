## 二、我依赖的稳定面（升级时重点核这些）

| 依赖点 | 当前形态 | 如果变了会怎样 |

| 顶层路线 | Generate / Create Template / Edit Native PPTX | 路线增加或更名 → 本文档与 agent 的路线表要改 |
| Default 生成七步 | 接料 → 建项目 → 模板候选 → Strategist → 图片 → Executor → 导出 | 步骤顺序变化 → 门位表失效 |

| 导出回执 | `[POSTFLIGHT]` + `validation/*.report.json` | 回执格式变化 → 解析要改 |

| 五页复读 | P05/P10/P15… 后重读 lock | 取消 → 长稿一致性风险上升，需自建重锚定 |

## 三、关键纪律（我按它设计的，如果它变了要重判）

1. **只有用户能确认**——代理不得代签、不得自动化提交、不得合成 payload
2. **`design_spec §IX` 是有序队列**——不增删并拆重排
3. **checker 只在门点跑**——不逐页跑
4. **最终门不过就不许导出**——导出器自己会拒绝缺报告
5. **`svg_output/` 是完整页面设计源**——模板/spec/lock 在导出时不供内容
6. **一条命令一条命令串行执行**
7. **`--json` 的报告是给程序的，stdout 是人类摘要**——不要互相替代

## 四、已知的本地差异（不是 ppt-master 的问题，是环境）

| 现象 | 原因 | 处理 |
|---|---|---|
| `python3` 退出 9009 无输出 | Windows WindowsApps 存根 | 改用 `python` |
| 依赖默认没装 | 沙箱环境干净 | 跑 `环境自检.md` 的一键安装 |
| 预览端口 6060 可能被占 | 多会话 | 换 `--port N`，或放弃预览（不阻塞生成） |

## 五、升级时怎么核

1. 读新版 `SKILL.md` 的 version 与本快照比对
2. 逐项核第二节"稳定面"，**只看变了的那几项**
3. 变了就更新：本文件 + `ppt-master调用契约.md` + agent 的路线表与门位表
4. **不要**在没核完之前直接跑生成——门位错位会导致"看着跑完了其实没验"的情况
