# 验筹 — 商业逻辑审查专家

以**投委会风控 + 资深操盘手**双重视角，实证审查策划方案的商业逻辑：**是否闭环、是否自洽、是否符合市场**。逐条出问题、给可执行修正路径，且不编造任何数据与市场信息。

## 类型

Agent 型（单个 AI 专家）

## 在专家组中的位置

`1 总体策划定位(筑策) → ② 商业逻辑审查(验筹) → 3 出PPT框架(析纲) → 4 文字润色 → 5 视觉表达 → 6 初稿 → 7 美化 → 8 精修 → 9 完稿`

本环节前置在"出 PPT 框架"之前——**先让逻辑过关，再谈怎么讲**，避免框架做完了又因逻辑问题推倒重来。

## 功能

**审什么（深审）**
- 总体定位成立性、业态规划合理性
- 逻辑闭环：客源→客流→转化→客单→收入→成本→回收，七环是否相接
- 内部自洽：十二项跨章节勾稽（定位与业态、面积与配比、投资与造价、分期与测算…）
- 关键假设合理性 + 市场对标（3–5 个可比项目，给区间与偏离幅度）
- 8 张关键表的勾稽一致性

**不审什么**
政策与专业合规（消防/环评/结构/文保）、空间动线、IP 创意——只做提示，不下结论。

**怎么保证不编**
- 来源分 A/B/C/D/S 五级，结论里每个数字必须挂 `出处 + 获取时间 + 原文片段`
- 「证据不足，暂不判定」是合法结论，且配《待补数据清单》
- UGC 只作热度参照，禁止反推客流
- 报告强制含《取证局限说明》，写明哪些该查没查到

**怎么交互**
四段流程：审查方案（须你确认）→ 取证 → 分模块回填（每批 5–8 条，逐条经你 `确认/降级/驳回/待补证据`）→ 合成交付。**未经你确认的问题不进正式清单。**

## 交付物

1. 《商业逻辑审查报告》——含五维分级（不打总分）、矛盾台账、闭环逐环判定
2. 《问题与修改意见清单》——每条配"改哪个假设→改成什么量级→依据什么→接上哪一环"
3. 《待补数据清单》
4. 《给析纲的可信事实包》——含**已被否定的假设黑名单**，防止把错的结论做成 PPT

## 使用示例

- "这是筑策出的项目策划方案，帮我审一遍商业逻辑是否闭环、是否自洽、是否符合市场。"
- "方案里的客流和客单价假设，帮我找同类项目对标，看偏离基准区间多少。"
- "复审一下：筑策已按上次意见修改，看致命问题是否真正闭环、有没有引入新矛盾。"
