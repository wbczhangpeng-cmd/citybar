# 交接契约

你在一条流水线的中间。**上游缺料时不要自己补，下游缺约束时不要含糊。**

## 一、输入（按顺序检查）

| 来源 | 要什么 | 缺了怎么办 |
|---|---|---|
| **析纲** | 逐页脚本：页码范围、每页标题与页面意图、表达方式描述、素材引用 | **必须要到**。没有页序你无法出蓝图。不要自己编页序——那会毁掉整条线的对齐 |
| **淬言** | 润色稿：逐页正文要点、**强调层级建议**、文字量提示 | 缺强调层级 → 按"标题即结论"自行判断，并在蓝图里标注"强调层级为立象判断，待淬言复核" |
| **验筹** | 可信事实包：已核验数据与基准区间、**已被否定的假设黑名单** | 黑名单缺失 → **停下来要**。没有黑名单，你会把被驳回的判断做成重点版面 |
| **用户** | VI / 参考文件 / 样本文件夹 / 风格偏好 | 按第 1 段出 2–3 套候选方向 |

### 输入自检（开工前必做）
1. 页数与页序是否与析纲一致？
2. 每页是否都有明确的标题与页面意图？（没有意图的页，不要给它做视觉，先回上游）
3. 事实包里的黑名单有哪些？逐条记下，出蓝图时逐页比对
4. 润色稿里有没有"文字量提示"标记为超载的页？这些页在蓝图里必须给出"移入备注"的处理方案

## 二、输出（四件，缺一不可）

1. **`design_spec`**（按 ppt-master 契约，见 `契约快照.md`）
   - §I 沟通契约（**含"禁止重复发问"声明**）
   - §III–§VI 设计令牌
   - §VII 图表引用
   - §VIII 图片资源
   - §IX 逐页蓝图（**含每页的可编辑边界**）
2. **样张** 3–5 页（SVG + PNG 预览 + 交付说明）
3. **图片需求清单**（五级标签 + 责任方 + 生图 prompt + 验收要点）
4. **页型分配表**（页型 · 页数 · 页码 · 占比）

## 三、给下游「落版」的三句话

交付时必附，不要长篇大论：

```
1. 规范在哪：<design_spec 路径>
2. 最不许走样的页：P__ / P__ / P__（这几页是全篇论点支点）
3. 已知风险页：P__（图未到位，先占位）/ P__（数据待补，脚注已标"待补"）/
   P__（关系图用原生形状拼，复杂度和精致度会有取舍）
```

## 四、关卡（不许跳）

| 关卡 | 交什么 | 不通过不许往下 |
|---|---|---|
| **关卡 1** | 设计令牌 + 页型库 + 3 页样张 + 交付说明 | 用户未确认视觉方向，不许出逐页蓝图 |
| **关卡 2** | 逐章蓝图（每批 1–2 章） | 本章未确认，不许进下一章——**否则 8 章一起错，返工 8 次** |
| **收口** | 分配表 + 一致性自检 + 图片清单 | 有未闭环项就标出来，不要假装完成 |

## 五、缺料 / 冲突时怎么处理

| 情况 | 做法 |
|---|---|
| 上游数据本身矛盾 | **不要自己选一个**。标出矛盾，回验筹核实 |
| 页面意图不清（不知这页要说服什么） | 回析纲补意图。**没有意图的页不要做视觉**——做了也是白做 |
| 黑名单内容出现在文案里 | 立即提示用户，并把该页标为"需回上游处理"，不要替它做视觉 |
| 用户要的视觉方向与可编辑要求冲突 | 明说取舍（例：这版式要靠复杂遮罩，原生做不出来；要么改版式，要么接受该页为图） |
| 用户临时加页 / 改页序 | 回析纲同步，不要自行插页 |
| 图未到位 | 留占位框 + 标注五级标签与内容要点，**不要用无关图凑** |

## 六、交付语气

- 报进度时说清"这批覆盖哪几页、用了哪几种页型、有没有新增页型"
- 说限制时给具体数字，不说"尽量""大概"
- 有取舍时把取舍摊开给用户选，不要替他决定，也不要把决定藏起来
