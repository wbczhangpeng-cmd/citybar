# 司南 · 自检清单

交付前逐项过一遍。**任一项打不了勾，就不要说“没问题”。**

---

## A. 开工（批章程之前）

- [ ] 项目类型已明确（文旅综合体 / 商业综合体 / 城市更新 / 其他），不是“大概是文旅吧”
- [ ] 受众已明确，**且可多选、排了决策链优先级**——它决定全篇语体
- [ ] 汇报时长与目标页数已有数（未定则给了默认并请用户确认）
- [ ] 手上现有材料已逐项盘点（有 / 无 / 什么形态），不是问“你有什么材料”
- [ ] 章程草案是**一页**，不是三页
- [ ] 章程每一条都能被违反、也能被检查（写不出“违反了会长什么样”的，已删）
- [ ] 三层结构齐全：共同底线 / 本项目加严项 / 决策权限表
- [ ] **用户已批准**，且登记了版本号与批准日期（不批不开工）

## B. 出交接包

- [ ] 第一项是“先贴章程 v__（已批 ____）”，一字不省
- [ ] 只给了**下一步**那一份，没有一次给七份
- [ ] 带什么材料写的是**路径或原文**，不是“按之前说的做”
- [ ] **未闭环项已逐条列出**，并写明“不许当成既定事实”
- [ ] **事实黑名单已随包转发**（若有）
- [ ] 本项目加严项已写入（禁用表述 / 语体 / 专业红线）
- [ ] 产出要求是**字段级**，不是“一份好的大纲”
- [ ] “回来给我什么”给了带文件名的清单

## C. 过闸

- [ ] 判据**逐条**给了结论，没有用“整体看起来没问题”带过
- [ ] 每条“过”都写了**依据**（哪一页 / 哪份文件 / 哪个数字）
- [ ] “无法核验”的条目**没有被算成“过”**
- [ ] 抽检写了**范围**（抽了哪几页、抽检项、结论）
- [ ] 判「打回」时写清了：缺什么 / 谁补 / 补完是否要全量重过
- [ ] 判「有条件过」时，条件三要素齐全：**具体内容 + 责任人 + 闭环时间**（缺一项就是打回）
- [ ] **没有替用户签“通过”**
- [ ] 内容是数字/结论改动类问题时，判得比别的严格（那是最严重的越位）

## D. 台账

- [ ] 先改 `project.json`，再用 `--render` 生成 `台账.md`（**没有手改 md**）
- [ ] 交付物登记了路径 + 版本 + 批准人 + 时间
- [ ] 新增的未闭环项与待办都已登记，带负责人和计划时间
- [ ] 跳步有 `skips` 记录，含理由与风险
- [ ] 是否忘了跑 `python scripts/check_project.py <项目目录>`
- [ ] 脚本退出码不是 1（有错误）

## E. 边界

- [ ] 没有替用户写任何内容（策划 / 文案 / 设计 / 排版）
- [ ] 没有改上游产物，发现问题走的是“退回”
- [ ] 没有评优劣（只查了门槛）
- [ ] 没有做内容判断（数字合不合理 / 句子好不好，都不是我的活）
- [ ] 用户催的时候，压缩的是流程，**不是闸门**
- [ ] 有跳步的，在归档清单里显式列了跳过项和由此产生的风险

## F. 交付归档

- [ ] 七步状态与实际一致（脚本核过）
- [ ] 定稿**单一版本**，没有并存的多个“最终版”
- [ ] 归档目录已建立：`归档/<交付日>_定稿/`
- [ ] 归档清单含：每步交付物 + 版本 + 批准人 + 跳过的步骤与风险
- [ ] 章程最终版本、台账最终版本已一并归档

---

## 三条最容易松的地方

1. **“无法核验”被顺手算成“过”。** 材料不全时最省事的做法就是放过——这一放，将来出事你也是责任人。
2. **交接包里漏掉未闭环项。** 下游看不到你的台账，你不写它就真不知道。这是整条链上最容易出事的一处。
3. **用户催就压闸门。** 流程可以压，闸门不能压。交付时那份归档清单，是将来唯一能说清“当时谁批了什么”的东西。
