# 闸门判据表

## 使用方式

在**每一次交接点**执行。**逐条过，逐条给结论**，不许用一句“整体看起来没问题”带过。

每条只有三种结果：

| 结论 | 含义 | 后续 |
|---|---|---|
| **过** | 核验通过 | — |
| **不过** | 缺件或不合格 | 判「打回」，写明缺什么、谁补 |
| **无法核验** | 材料不全，核不了 | **不算过**。写入验收单，交用户自行判断 |
| **需回流** | 问题归属于上游某一棒 | **必须退回上游定点改**，改完重判。**此时不许开下一棒** |

**无法核验 ≠ 通过。** 这是整套机制里最容易滑的地方。材料不全时诚实说“这条我核不了”比假装过了有用——假装过了，出问题时你也是责任人。

## 公共前置：交接三核（**每一道闸门都先过这三关**）

下面七道闸门的判据是**分步的**；这三条是**所有闸门共用的**，先过三核再逐条过判据。

| # | 核什么 | 怎么核 | 不过的处置 |
|---|---|---|---|
| **公-1** | **清单真伪** | 交付方交出「覆盖面清单」（索引表/对照表/落点表/覆盖表/页型分配表）时，要求它给出**抽验记录**：随机抽 5 条回源头核。**5 条里 1 条错 → 整张作废重做**，不修补 | 打回，重做清单 |
| **公-2** | **引用存在** | 跑 `scripts/check_file_refs.py --root . --root 交付物 --include-plugins` | 报「缺失」→ 补建文件或改引用，两条路选一条 |
| **公-3** | **放行三性** | ① 可编辑性 ② **内容可见性** ③ 事实准确性，**三条分别过**。凡 PPT 类交付物，② 跑 `check_content_visibility.py` | 任一条不过 = 整体不过 |

**为什么这三条要单独立在这里**：它们对应本组踩过的三个真事故，而这三个错误的共同特征是——**读起来完全通顺**。

- 清单漏 14 处（「传」漏 6 页）：文字通顺，因为清单长得就像对的
- 连续三棒引用不存在的文件：文字通顺，因为**它描述的东西"应该有"**
- 55/55「可编辑性全合格」的稿子里 14 页内容在画布外、一页丢 443 字：报告通顺，因为**它只回答了另一个问题**

细则见 `交接核验协议.md`。

## 公共前置 B：问题归属与回流（**每道闸门前先做这一件**）

**事故**：一个 58 页项目跑完全链，**7 道闸门 7 次全 pass、0 次退回、10 余条问题被"记账"消化**。结果析纲的 29 页只有施工备忘没有文案 → 落版照搬 → 定稿里 8 页仍是骨架。问题从第一步一路带到交付。

**每条问题必须带一个归属，四条路，没有第五条**：

| 归属 | 处置 |
|---|---|
| 归本棒 | 就地改，记账 |
| **归上游·X** | **必须回流**。不许代改 / 不许记账了事 / 不许另建补充文件绕过 |
| 归用户 | 进《待确认清单》 |
| 归甲方 | 标 `{待补}`，**唯一**合法的"带病前进" |

**「有条件通过」只剩一种合法用途**：条件来自**外部**（甲方数据未到 / 用户口径未定）。条件来自上游 = 没做完 = 退回。

**回流是「定点重入」不是「整棒重跑」**：只把 `归上游` 的条目 + 需要改的位置交给那一棒，续接唤醒，它改完回传 v2，你只重判改过的地方。**同一棒最多 2 次，第 3 次升级用户**。

**为什么必须定点**：整棒重跑要十几分钟 + 大量上下文，所以过去没人愿意退 —— **机制失效不是人不守规矩，是粒度太粗**。

**闸门结论因此只有四种**：通过（无未处置的归上游问题）/ 回流 / 打回 / 外部挂起。

## 闸门零：项目开工（批章程之前）

| # | 判据 | 怎么核 |
|---|---|---|
| 0-1 | 项目类型已明确（文旅综合体 / 商业综合体 / 城市更新 / 其他） | 问用户，或从材料判断；判断不了就问 |
| 0-2 | 受众已明确（可多选，且排了决策链优先级） | 未明确不许开工——它决定全篇语体和侧重 |
| 0-3 | 汇报时长与目标页数已有数 | 未定则给默认（30 分钟 / ≥40 页）并请用户确认 |
| 0-4 | 手上现有材料已盘点清楚（有/无、什么形态） | 逐项列，别问“你有什么材料”这种开放式问题 |

**不过的处置**：不批章程，不开工。缺 0-1/0-2 时尤其要停——这两项错了，后面七步全白做。

## 闸门一：筑策 → 验筹

| # | 判据 | 怎么核 |
|---|---|---|
| 1-1 | 三段式齐全：项目认知与基础分析 / 项目定位 / 具体策划 | 看目录结构 |
| 1-2 | 8 张关键表齐全，或有明确的缺项说明 | 区位场地评价、竞品对标、客群画像、功能配比、业态面积配比、定位矩阵、运营收益测算、分期实施 |
| 1-3 | 关键数字有来源标注 | 抽 5 个核心数字（客流、客单、投资、坪效、回收期）看有没有出处+年份 |
| 1-4 | 一句话定位 + 定位矩阵存在 | 找不到就是定位还没收敛，不许进审查 |

**不过的处置**：打回筑策。缺 1-4 是最常见的——很多人直接跳到策划，定位是散的。

---

## 闸门二：验筹 → 析纲

这一道最严，因为审查结论是后面所有页面的地基。

| # | 判据 | 怎么核 |
|---|---|---|
| 2-1 | 整体结论为「可推进」或「补证后可推进」 | **「需重大修改」或「不建议推进」不许进第 3 步**，必须回筑策改完再复审 |
| 2-2 | 问题清单已逐条经用户确认，无「待确认」状态残留 | 逐条看状态列；有残留的先让用户处理完 |
| 2-3 | 《事实黑名单》已随包交付 | 空也要有文件，写“本项无”，不能没有 |
| 2-4 | 《给析纲的可信事实包》已交付 | 含已核验数据 + 基准区间 + 黑名单。没有这个，析纲会照抄被否定的假设 |
| 2-5 | 《取证局限说明》存在 | 写明哪些该查未查到。这一章缺失说明审查不完整 |

**不过的处置**：
- 2-1 不过 → 打回筑策，不进第 3 步
- 2-2/2-3/2-4 不过 → 退回验筹补齐，可同时让筑策先改 P0 项（并行不阻塞）
- 2-5 不过 → 有条件通过，但要求补上

## 闸门三：析纲 → 淬言

| # | 判据 | 怎么核 |
|---|---|---|
| 3-1 | 页数达标：默认 ≥40 页，或已有用户批准的调整 | 数页；不够看是否获批 |
| 3-2 | 目录结构与页数分配已确认锁定 | 用户明确说过“就按这个” |
| 3-3 | 逐页字段齐全 | 抽查 5 页，看是否都有：页码/章节/标题/意图/核心结论句/要点/表达方式/文字量/演讲备注/素材引用/初步文案 |
| 3-4 | 前置固定项就位：封面 / 目录 / 摘要（总结） | 缺摘要就是没前置结论，汇报逻辑会塌 |
| 3-5 | 技术图纸页只排标题、页面留空，且写明呈现方式（以图为主） | 看是否越位画了图 |
| 3-6 | 章程第二条（禁用表述、黑名单）已在脚本中体现 | 抽查 3 页，看有没有引用黑名单内容 |
| **3-7** | **每页「本页图片需求」落到 P / S / O 三档之一** | 跑 `check_outline_narrative.py`。写「可配图」＝没判，退回流 |
| **3-8** | **P 档页数 ≥ 总页数 35%** | 同上脚本报占比。文旅 / 商业综合体 / 景区类底线，不到就是资料汇编 |
| **3-9** | **可自行生成的图（分析图 + 意向图）不为 0** | 同上。全是"等甲方" → 落版必然 0 图 |
| **3-10** | **图源缺口已按责任方分开**：我方自绘 / AI 生成 / 需甲方 / 需设计单位 | 看清单有没有把"能自己画的"标成"待甲方"（这是 0 图汇报的直接病根） |

**不过的处置**：打回析纲。3-6 不过时注意——析纲可能拿不到黑名单，先确认它有没有收到验筹的事实包。

## 闸门四：淬言 → 立象

| # | 判据 | 怎么核 |
|---|---|---|
| 4-1 | 与析纲逐页对应，不丢页、不多页 | 页数比对 + 页码序列比对 |
| 4-2 | **数字与结论零改动** | 抽检每章 2–3 页，与析纲原文/验筹事实包比对 |
| 4-3 | 《修改对照表》已提供 | 无对照表就无法逐条验收，也无法判断是“改好了”还是“改没了” |
| 4-4 | 每页有「强调层级建议」与「文字量提示」 | 没有这个，立象不知道哪句该做大字 |
| 4-5 | 事实黑名单内容未出现在任何页面 | 全文检索黑名单关键词 |
| 4-6 | 章节结构未变 | 比对章节标题 |

**不过的处置**：
- 4-2 不过 → **严重**。打回，并要求说明为什么改动了数字。这是淬言最需要防的越位
- 4-1/4-4 不过 → 打回补齐
- 4-3 不过 → 有条件通过（内容可用，但验收链断了，需补）

**抽检记录**：把抽到的页码写进验收单，让用户知道覆盖到哪。

## 闸门五：立象 → 落版

| # | 判据 | 怎么核 |
|---|---|---|
| **5-0** | **表达型分配表已出**：全篇每页都有 E1–E9 之一 + 图文配比 + 依据 | 逐页看。**这是设计的第一层，排在令牌之前**。缺了说明只在做样式，没在做设计 |
| **5-0b** | **相邻页配比无连续重复**（不要连续 3 页 5:5） | 顺着看一遍。配比平了，阅读节奏就平了 |
| **5-0c** | **没有"判不出来"的页** | 有 → 那页有两个核心，退回析纲拆页（`归上游·析纲`） |
| 5-1 | `design_spec` 通过 schema 校验 | 跑校验；无校验能力的，逐节检查 §I–§IX 是否齐全 |
| 5-2 | 页型使用不超 15 种 | 统计页型种类；超了说明在为单页造特例 |
| 5-3 | 样张 3–5 页且已获用户确认 | 问用户“样张你点过头吗”，没点头不许批量 |
| 5-4 | **逐页图位分配表**覆盖全篇，每张图带五级标签 + 必要性 P/S/O + 位置尺寸比例 + 裁切规则 + 责任方 + 最晚到位 | 逐项看。**只有"需求清单"没有"图位分配"不算过**——需求是愿望，图位是施工指令 |
| **5-4b** | **图源缺口分责表已出**，且「自绘 / AI 生成」两栏 ≠ 0 | 是 0 就说明把能自己做的活全推给甲方了 |
| **5-4c** | **实景类缺口已在出清单时形成索取清单**（不是等落版发现） | 看有没有带「向谁要、什么景、什么时点」 |
| 5-5 | 每种页型声明了「可编辑边界」 | 缺了会在精修阶段才发现改不动 |
| 5-6 | 沟通契约已写入 §I，且声明「禁止 Strategist 重复发问」 | 少了这一条，落版会重问一遍受众和意图，把前面五步推翻 |
| 5-7 | 令牌无形容词 | 全文搜“大气/简洁/高级/灵动/呼吸感”，命中即不过 |

**不过的处置**：打回立象。5-7 不过是最常见的低级错，也最容易改。

## 闸门六：落版 → 琢磨

| # | 判据 | 怎么核 |
|---|---|---|
| 6-1 | pptx 能打开，页数与设计一致 | `python-pptx` 读一遍 |
| 6-2 | **可编辑性零不合格** | 跑 `check_editability.py`，全篇无不合格页 |
| 6-3 | 无整页截图 | 同上脚本的「疑似整页位图」判定 |
| 6-4 | 偏差记录 + 已知薄弱页清单 + 缺口清单齐全 | 三份都要。薄弱页清单缺了，琢磨要从头再判断一遍 |
| 6-5 | **项目工作区路径已交出** | `svg_output/` + `design_spec` + `spec_lock` + `images/`。**缺了琢磨只能改 pptx，改不了源** |
| 6-6 | 图片状态已标注（已生成 / 待甲方 / 占位） | 逐张看；未标注的后面会漏 |
| 6-7 | 演讲备注已写入 pptx 备注栏 | 抽查 2 页 |
| **6-8** | **内容可见性 0 越界 / 0 溢出 / 0 碰撞** | 跑 `check_content_visibility.py`。**这条与 6-2/6-3 是两个正交判据，谁也替代不了谁** |
| **6-9** | **可自行产出完成率 100%**（分析图 / 意向图 / 装饰图全部做出来了） | 跑 `check_image_coverage.py` 对照《图文到位率报告》。**这一条与甲方给不给材料无关，纯属我们的活干没干完** |
| **6-10** | **P 档图（可自行产出部分）到位 100%**；外部提供的 P 档缺失已单列为「交付前置条件」 | 缺 P 档图 = 那页论证不成立，不许定稿 |
| **6-11** | **全篇图片覆盖页占比达标**，零图页逐页有理由 | 跑脚本看覆盖率。**零图页超过 20% → 退回重排**（不是补图，是这页本来就不该这么排） |
| **6-12** | 意向图全部带「意向图」标注；分析图全部带数据出处 | 逐张看。**缺标注是合规问题，不是美观问题** |

**不过的处置**：
- 6-2/6-3 不过 → 打回返工，不许带病进精修（精修会把它变得更难查）
- **6-8 不过 → 必须返工**。这是本项目真实踩过的：6-2/6-3 全过（55/55 合格、图片覆盖 0%），而实际 14 页内容在画布外。**6-2 查的是"是不是图片冒充"，6-8 查的是"内容在不在画面里"，两回事**
- 6-5 不过 → **必须补**。这是交接链上最容易漏的一项，漏了后面整段精修都要降级

## 闸门七：琢磨 → 交付

| # | 判据 | 怎么核 |
|---|---|---|
| 7-1 | 可编辑性复验零退化 | 复跑脚本，与落版基线逐页对比 |
| 7-2 | 跨页一致性检查通过，或残留已说明 | 跑 `check_deck_consistency.py`；未通过项要有解释 |
| 7-3 | 所有 L2 改动均有用户批准记录 | 逐条对；没有批准记录的 L2 改动视为越权 |
| 7-4 | 《已知残留清单》存在，每条写明为什么修不动 | 没有这份清单 = 琢磨认为全部完美，通常不成立 |
| 7-5 | 定稿单一版本（不并存多个“最终版”） | 看目录；有 `v3_终稿_最终` 这类命名就清理 |
| 7-6 | 章程要求的交付物齐备 | 对章程第二层逐项核 |
| **7-7** | **内容可见性复跑仍是 0 / 0 / 0，且与落版基线逐页一致** | 跑 `check_content_visibility.py` 与前一次结果对撞。**精修把文字改长改短都可能造成新溢出** |

**不过的处置**：打回琢磨。7-3 不过时要特别警惕——L2 越权意味着用户没看过就改了，这在保护自己的意义上比页面难看严重得多。

## 附：跳步时的加严规则

用户有权跳过某一步。跳过后，下游闸门要补上缺失的判据：

| 跳过的步骤 | 下游闸门加严项 |
|---|---|
| 跳过验筹 | 闸门三新增「事实黑名单是否存在」——没人产出它，则由司南与用户现场确认一份 |
| 跳过淬言 | 闸门五新增「禁用表述扫描」——原本由淬言负责 |
| 跳过立象 | 闸门六新增「可编辑边界声明」——由落版现场声明并经用户确认 |
| 跳过析纲 | **不建议跳**。跳了就没有页序，落版会自由发挥，等于重做 |

跳步必须记入台账：`跳步（用户决定）` + 时间 + 理由 + 由此产生的风险。

**不许静默跳步，也不许因为用户催就假装那步不存在。**
