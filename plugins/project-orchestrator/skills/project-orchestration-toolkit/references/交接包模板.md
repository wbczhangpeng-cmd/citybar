# 交接包模板

**三个字段。写完就能交，不用凑。**

> 上一版是六个字段（本段结论／交付物清单／本段遗留／下一棒要带什么／闸门结论／问题归属表）。
> 六个字段的实际效果是：写的人凑格式，读的人只找两样——**"我该拿什么"和"我别踩什么"**。所以压到三件。

---

## 模板

```markdown
# 段X 交接包

## 一、本段定了什么

<三五句。说清这段确定了哪些决策，以及哪些还没定。>

- 已定：<逐条，一句话一条>
- 未定：<逐条，标明卡在谁身上——甲方／主人／下一棒>

## 二、下一棒要干什么

**先看**：<文件路径> 的 <第几节／第几页> —— <为什么先看这个，一句话>

**必读清单**：
| 文件 | 路径 | 用途 |
|---|---|---|
| | | |

**别踩**（本段踩过或差点踩的坑）：
1. <坑是什么 + 正确做法>
2. ...

**产出要求**：<这一棒必须交出什么，格式与体量>

## 三、没解决的

| 事项 | 归属 | 现在怎么处理 |
|---|---|---|
| <问题> | 归甲方 | 标 `{待补}`，不阻塞 |
| <问题> | 归主人 | 已在待确认清单第 N 项 |
| <假设> | 已否掉 | **写进黑名单，下游不得使用** |
```

---

## 「别踩」这一栏最重要

它是交接包里唯一"只能由走过这一段的人写"的东西。

**写什么**：本段真实踩到的坑、差点踩的坑、以及"看起来对但其实错"的判断。
**不写什么**：泛泛的注意事项（"注意保持一致性"这种等于没写）。

好的样子：
> 「客户把'总游客量'当'过夜游客量'用了一次，我们跟着算了一版二消，后来发现口径错了。
> **正确做法**：二消只能用过夜游客量做分母。」

坏的样子：
> 「注意数据准确性。」（谁都知道，等于没说）

---

## 问题归属表（必填，但不单列一节）

直接在第三节的表格里体现。**`归上游` 的条目只允许三种状态：已回流 / 已回 v2 / 已复核。不许出现「已知未处理」。**

---

## 一条禁令

**交接包里不许写"详见某某文档"就完事。** 要么把关键结论抄进交接包，要么给到具体章节号。

> 真实事故：连续三棒引用同一份从未存在过的"附录文档"，每一棒都觉得"上游给了"。**跑一遍 `check_file_refs.py` 就不会发生。**
