# 台账规范

**一个真相源，两个文件**：`project.json`（唯一真相源）+ `台账.md`（由 json 渲染，不许手改）。

## 记什么（五个字段）

```json
{
  "project": { "name": "", "type": "文旅|商业|城市更新|住宅|片区",
               "charter": { "version": "v1", "approved": true } },
  "stages": {
    "1_立项": { "status": "in_progress", "gate": "回流", "note": "验筹 F-01 待改" },
    "2_文本": { "status": "pending", "gate": null }
  },
  "deliverables": [
    { "stage": 1, "owner": "筑策", "path": "交付物/xxx.md", "version": "v9", "status": "current" }
  ],
  "open_issues": [
    { "id": "F-01", "owner": "筑策", "type": "归上游", "desc": "", "state": "已回流" }
  ],
  "rulings": [
    { "id": "R-01", "topic": "", "decision": "", "by": "主人", "date": "2026-10-26" }
  ]
}
```

- `gate`：`通过` / `回流` / `打回` / `外部挂起`
- `deliverables.status`：`current` / `superseded`
- `open_issues.state`：`已回流` / `已回 v2` / `已复核` / `待主人` / `待甲方`。**不许出现"已知未处理"**
- `rulings`：**主人裁过的事记在这里**——这是"终审不可重提"的唯一执行依据

## 不记什么（比上一节重要）

| ❌ 不记 | 为什么 |
|---|---|
| **md5 / 字节数 / 行数** | 上次为这些打了十几轮，**对结论贡献 0**。文件一改值就变，一有时点差就要争（"41,164 还是 45,226"），而且**永远争不出结果，因为两个都对** |
| 对话轮次、耗时 | 没人看 |
| 专家自报的"我做了什么" | 那是交接包的事 |

**需要确认"是不是同一份文件"时，看版本号和文件名就够。** 真要对比内容就直接比内容——比看 md5 可靠，也不占台账。

## 主人问"现在到哪一步"时

先看 json 再答，不凭记忆。**不超过五行**：

```
段X <状态>　放行：<通过/回流/外部挂起>
未闭环：<open_issues 里 state 非"已复核"的，按 owner 分组>
等你定：<state 为"待主人"的，附编号>
```

主人问进度不是要报告，是要知道卡在哪、该谁动。

## 一条纪律

**主人每次裁定后，立刻记进 `rulings`。** 没有记录，"你说过了"就说不清。
